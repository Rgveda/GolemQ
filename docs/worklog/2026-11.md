**2026-11-16（续）：`--review` 代码复审 —— 7 处问题（**均未修**，仅记录+复现）**

上一会话在 `重新审查 --review 代码` 处撞 1,048,576 token 上限中断；本条目是补完的复审结果。
全部结论都有可执行复现（除 F7 为读码+实测取数边界），修之前先看这里。

* **F1（高）`--pct-of-cores` 小数被 `int()` 截成 0 ⇒ 整条管线串行**
  `pipeline/review/pipeline.py:308`：`cpu = int(pct_of_cores) if pct_of_cores else 0`；
  随后 `elif 0 < cpu <= 1` 永远进不去。CLI 默认 **0.32**、`tools/run_review_shard.py`
  默认 **0.5** 都会落到 `cpu=0` ⇒ `BasePipeline.run_codes(pool_size=0)` 串行，而且
  并行横幅（只在 `pool_size>0` 分支打印）**一行都不出** —— 与 2026-11-12 主流管线
  「直接卡死没提示」同一个坑。主流已用 `worker_count()` 修过（其 docstring 就是
  这个事故），`compact/pipeline.py:148` 仍是同款坏实现。
  修法：复用 `mainstream.pipeline.worker_count`（必要时先挪到共享位置），**别写第三份**。
* **F2（高）60min ChipDist 四列在盘中 bar 上用了**当日收盘**（未来函数）**
  `hour_extra.chip_ratios_from_abs` 用 `days.searchsorted(targets.normalize(), 'right')-1`
  选分子；`chip_abs` 含当日 key（15:00 目标需要），于是 10:30/11:30/14:00 也取到当日
  收盘算出的成本。实测 000711 2025-12-08：`chip_cost_by_day` 只请求盘中 → key=12-05
  （1.68/1.72/1.86/1.89），只请求 15:00 → key=12-08（1.68/**1.73**/1.86/1.89）；
  混合 targets 时 10:30 的 `cost15Prz` 分子 = **1.7300（当日）**，不是前一日 1.7200。
  该函数被 `review`（`day_sample_step`）与 `tools/backfill_hour_extra.py` **共用**，
  两条路径同病。修法：盘中目标改 `searchsorted(..., side='left')-1`（取前一交易日），
  15:00 保持当日；改完两侧仍同源。
* **F3（中）`coldstart._core_daily` 的 None 分支是 NameError**
  `coldstart.py:47`：`feats = features if feats is None else feats` —— `features` 未定义。
  当前唯一调用方都传了 `feats`，所以没炸；`_core_daily(day)` / `_coldstart_row(day)`
  （日线 ≥30 根时）直接 `NameError: name 'features' is not defined`（已实测）。
* **F4（中）15min 族**无法自愈**：60min 目标为空时 `zen_snapshots` 被跳过**
  `StepRunner.run` 对 `len(targets)==0` 的 step 直接 `continue`；`zen_snapshots` 同时
  负责填 `_minute15_rows`。实测（60min targets 空、15min targets 非空、families=15min）：
  `StepRunner` 输出 `{}`，`zen_snapshots` 未执行 ⇒ 15min 缺行**永远补不上**（除非
  `--force` 全量重算）。修法：跳过判据加入「有被选中且目标非空的 step 依赖它」。
  附带的窄口：`persistence.persisted_keys(min_columns=1)` 把**部分列**已写的行当已持久化，
  与「`_write_family` 只写 frame 里存在的列」叠加后，半行也会被永久跳过。
* **F5（低）死代码/平行实现**：`hour_extra.pivot_counts()` 与 `pivot_stats()` 是同一批
  CZSC 中枢的两份实现，且 `pivot_counts` **无任何调用方**（只在 `__all__` 里）；
  `minor.minor_signals_step()` 只剩测试在用（compat 入口，方向是错的就删）。
* **F6（低）同一 day target 的 `_day_row` 算两次**
  `steps/daily.py:257-259`：`sample_rows[T]` 与 `day_rows[T]` 各调一次（值是同一份）。
  代价小，但属于「算过就免算」的反例。
* **F7（低）`--offset <日期>` 在三族间边界不一致**（实测 000711，offset=2025-12-08）：
  `as_of = 00:00` ⇒ day 帧最后一根 **12-08**，60min/15min 最后一根 **12-05 15:00**。
  即截止日只对日族生效。要么把分钟族的 end 补到 23:59:59，要么明确写成「日族含当日、
  分钟族不含」——现在是隐式的，容易被当成数据缺口。
