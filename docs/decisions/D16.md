# D16. 参考数据的**刷新闸**：**按集合**分阈值，复用 supervisor 的签到表

- **编号**：D16
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D16 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：`--save` 的参考数据段加一道新鲜度闸 —— 距上次**成功完成**
不足该集合 TTL 的**直接跳过、连源都不选**（省 HTTP 查询的地方就在这）。
**阈值按集合分**（`refdata_save.TTL_HOURS`，形如 ``(盘中, 盘后)``）：

| 集合 | 盘中 | 盘后 | 为什么 |
|:--|--:|--:|:--|
| `stock_list` / `stock_block` / `etf_list` | 5h | 24h | **名单**类，盘中有新上市/停牌/调样 |
| `stock_info` | 24h | 24h | 股本、上市日、省份/行业 —— **日内根本不变** |

「盘中」判定**复用** `date_utils.GQ_util_if_tradetime`（真交易日历 `TRADE_DATE_SSE`，
含 9:15 集合竞价）；``(x, x)`` 的表项直接返回、不查日历。

**存储：复用 `supervisor` 的签到表，不自建表。** 每个集合占
`GOLEMQ.function_checkins` 一行（`function_name = 'refdata:<集合>'`）——
`function_checkin.py` 的 `expired_timestamp` 与 TTL **完全同构**，再养一张表就是第二个轮子。

为此给 supervisor 补了两处**向后兼容**的小口子：

* `last_checkin(function_name)` —— **只读**的查询口。`checkin_function` 的 `allowed`
  是「抢名额」语义（**调用即记账**，跑挂了也把时间戳推后），**不能**拿它当
  「上次成功于何时」的读口。故「先读 → 只在成功后写」。
* `caller_ip` 可选传入，见下。

### ⚠️ 复用踩出来的两个坑（都已修）

**① `resolve_caller_ip()` 返回的是「网关」，而且会抖。** 本机是 `192.168.*` 时它会走到
`get_gateway()`；`get_gateway()` 失败又退到**硬编码**的 `192.168.1.1`。实测同一会话里
写下了 **`192.168.1.1` 与 `192.168.50.1` 两条** `refdata:*` 记录 —— 而**计时键抖动 =
记录查不到 = 刷新闸静默失效**。故 `refdata` 用它自己钉死的键
（`_caller_key()` → `host:<主机名>`），并给 supervisor 的 `checkin_function` /
`last_checkin` 加了可选 `caller_ip`。顺带：`--save` 不再每次起一个 `ipconfig` 子进程。

**② `get_gateway()` 在本项目自己的要求下必然失败。** 项目要求 `PYTHONUTF8=1`，
于是 `subprocess.run(..., text=True)` 按 UTF-8 解码 —— 而 zh-CN 的 `ipconfig` 吐 GBK，
**解码失败打死 subprocess 的读线程** → `result.stdout` 变 `None` → `NoneType.split`，
每次调用都在屏上留一段线程 traceback。已加 `errors='replace'`。

### 其他口径

* 起算点是「上次**成功完成**」而不是「上次启动」；只有 `status == 'ok'` 才记账
  （`skipped` 不记，免得一次空跑把集合冻住一整个 TTL）。
* 从没成功过（`age is None`）→ 按「该取」处理，不会把新库冻住。
* `--save-refresh` 强制忽略闸、本次一律重取。
* **记账失败绝不抛**：签到表在运维库（`GOLEMQ`），连不上 / 建不出索引都可能 ——
  为记账把一次**成功的取数**变成失败是本末倒置。失败只是刷不成新、下次照常重取。
* 被闸拦下的条目打 `entry['cached'] = True` → banner 点亮（`●` 白），
  CLI 的「一个都没成」判据也算它「有」。

对参考数据（日内基本不变）而言是合意的；要按「交易日整段」算盘中，改
