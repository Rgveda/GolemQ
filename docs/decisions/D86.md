# D86. 周线 `4QPwrlnWek` 回填口径：回看长度 / 周标签 / 成熟度门槛

- **编号**：D86
- **日期**：2026-11-22
- **代码**：`tools/backfill_quad_pwrln_wek.py`
- **测试**：`test_cases/tools/test_quad_pwrln_wek.py`

## 背景

用户要「全 code 从 2018-01 起算周线、落 60min、出逐日截面 CSV」。原工具
`tools/backfill_quad_pwrln_wek.py` 只支持 2024-06 以后的回填，直接拉长区间会
踩三个坑 —— 每个坑都**不报错，只是数变低**。

## 三个口径（都已改）

### ① 回看长度：不是随便一个 2016

`calc_four_quadrant_boost`（`analysis/quadrant_jit.py`）里 `4QPwrln` 是

```
QUADRANT_POWERLINE = (close>MA5)+(close>MA13)+...+(close>MA233) - 3.8
```

最长窗口是**周线 MA233** ⇒ 233 周 ≈ **1,165 根日线 ≈ 4.5 年**。原来写死
`start='2016-01-01'`，对 2018-01 的首批输出只有约 100 周，MA233 全 NaN ⇒
`close > NaN` 恒 False ⇒ 该项恒 0 ⇒ **powerline 系统性偏低**。

实测 2018Q1（2016 起 vs 2009-10 起）：000711 `-3.8 → -1.8`，600519 `1.2 → 3.2`。

现为 `--day-start`，默认 `start − 3000 自然日`（≈2,050 交易日）。
`--start 2018-01-01` ⇒ 日线从 **2009-10-15** 起。库里日线可回溯到 2007-01
（000711 有 3,768 根），够。

### ② 周标签 = 该周最后一个实际交易日

`analysis/timeseries.weekly_ohlc` 的周索引是**该周最后一个实际交易日**
（不是 `W-FRI` 的周五标签）。所以对某日 `D` 直接 `ffill`，拿到的就是
「D 之前已走完的那一周」；只有当 `D` 恰好是该周最后交易日时才拿到当周。
**不需要**按 15:00 再分支。

⚠️ 区间被截断时有例外：`--end 2024-07-31`（周三）会让最后一根周线被打成
「只含 3 天」的标签=07-31，而同周前几天用的是上一完整周 —— 看起来像跳变。
修法：用**延伸到 `end + 10 天`的交易日历**判「这一天是不是该周最后一个
交易日」，不是就回退上一完整周。修正后 2024-07-31 由 -2.8 回到 -3.8。

### ③ 成熟度门槛：`--min-weeks 233`

`_weekly_series` 原有的 `len(day) < 520` 闸有两个问题：

1. **面板随 `end` 变**。门槛量的是「截止到本次 `end` 的总日线数」，于是
   end=2024-07-31 的跑法把 2022~2023 上市、到 2024-07 不足 520 根的码
   **整只丢掉**，面板封顶 4,644。同一历史日期在两份 CSV 里中位数不同
   （2022-10 之后 83 天 Med、55 天 Mode 不一致）—— 历史值不该依赖于
   「你跑到哪天」。
2. **520 根日线挡不住 MA233**。520 根 ≈ 104 周，远不够 233 周，新股上市头
   4.5 年 powerline 结构性偏低却照样进截面。

现按「该码周线序列在 D 之前已有 233 根」判定（用序列内位置，不必再查日线），
不足的日期填 NaN 不进截面。`--min-weeks 0` 可关。

## 结果（2018-01-02 ~ 2026-11-20，2,012 交易日）

| 口径 | 面板 | 说明 |
|:--|:--|:--|
| 全码 | 3,291 → 5,297 | 含新股，结构性偏低 |
| `--min-weeks 233` | **2,226 → 4,615** | 交付口径 |

两者差异：**733 天 Med 不同（均值 +0.353，最大 +2.0）**、
**391 天 Mode 不同（均值 +0.954）**。按年看 2021/2022/2023 最严重
（dMed +0.83/+0.95/+0.71，dMode +2.23/+3.18/+2.73）—— 正是 IPO 高峰，
新股把全码中位数往下拖了近 1 档。

交付 `output/mas_quad_pwrln_wek_2018_2026.csv`（成熟码口径）。旧的
`_2018_2024.csv` 因面板被 `end` 截断已删除。

## 交叉验证

## 遗留

massive 表 15:00 行只有 2022-06-16 起，2018~2022-06 无行。用户口径是
**全区间不写 massive**，避免插出只有两列的稀疏行 —— 那段只在 CSV 里。
