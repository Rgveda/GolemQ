# D14. `--save` 收口成 **`<SOURCE>` 一个开关**（`--save-x` / `--save-qmt` 删除）

- **编号**：D14
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D14 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：`--save` 只收 `tdx` / `pytdx` / `qmt` 三个取值，
**`x` 与 `all` 不再接受**；`--save-x` / `--save-qmt` 两个开关**删除**。

| 命令 | 做什么 |
|:--|:--|
| `--save tdx` / `--save pytdx` | 参考数据（4 个集合，见下）+ K线 + xdxr/adj。**两条完全等价** |
| `--save qmt` | 只做参考数据（强制 qmt 源，3 个集合）；K线/xdxr/adj **跳过**（只有 pytdx 供得了）|

**各源能供的集合**（表在 `refdata_save.REFDATA_BY_SOURCE`）：
`pytdx` = `stock_list` / `stock_info` / `stock_block` / **`etf_list`**；
`qmt` = 前三者（适配器没声明 `etf_list`）。

**理由**：三个开关表达同一件事、语义还互相重叠（`--save-x` = 「5 集合 + 每集合
自动选源」，`--save tdx` = 「3 集合 + K线」）。收成「源名即开关」一个概念。
`pytdx` 与 `tdx` 并列收录：适配器的真名就叫 `pytdx`（`pytdx_source.py` 的
`name = 'pytdx'`），`tdx` 只是命令面的历史名字。

**弃掉的能力（明确记账，不静默）**：

* **每集合自动选源**没了 —— `--save <SOURCE>` 只走指定源。但 tdx 侧仍带
  `exclude_sources=('akshare',)`，且 `stock_list` 仍由 tdxaidata 补北交所那 351 只
  —— 那是**承重的**（D11 拒绝的方案 A），**没有**被这次收口动到。
* **`etf_list` 的入口补回来了**（同日修复，见下）。`financial` 不受影响
  （本来就走 `--migrate-financial`）。
* 「只做参考数据」这个模式没了：要限集合用 `--save-collections`。

**未改**：`save_refdata` 的取数逻辑一行没动 —— 收口的是**命令面**，不是取数语义。

**`--save qmt` 必然失败，且是刻意的**：`QmtSource.available()` 恒 False（D13 的
「只留结构」），故三个集合全报不可用。判据是「**一个都没成**」→ 非零退出；
**部分失败不中断**（K线照跑），逐集合状态照打 —— 别让它装作成功。

**`etf_list` 补进 `--save tdx`（同日）**：`--save-x` 被删后它一度没有 CLI 入口。
补回时发现**必须允许 akshare**，理由已实测（2026-10-09）：

| 源 | `etf_list` 实测结果 |
|:--|:--|
| `akshare` | ✅ 一次调用 **1694 行 / 1.4 秒** |
| `tdxaidata` | ❌ **0 行** + `[错误码 2] 股票代码错误`（`get_trackzs_etf_info`） |
| `pytdx` / `qmt` | 不声明该集合 |

即：`pytdx`/`qmt` 都供不了，`tdxaidata` 那条路是坏的 → **akshare 是唯一可用源**。
所以 `--save` **不再传 `exclude_sources=('akshare',)`**（原来那个排除对另外三个集合
本就是空操作 —— akshare 只出现在 `etf_list` / `financial` 的优先级里 —— 却恰好会把
`etf_list` 推给坏掉的那条路）。⚠️ 别与 `financial` 混淆：当初「避开 akshare」避的是
`financial` 的**逐只**路径（≈46.5 小时），本命令从不碰它。
`etf_list` 的 upsert 键是 `['code']`、**无差量删除**，故补写是纯 upsert，不会误删。

**连带 —— 状态 banner**（`core/presentation.Banner`）：把**整条 `--save` 流程**
画成固定表头（参考数据 4 → K线 3 族 × 6 频率 → 复权 2），随进度点亮。
**状态只由一个点表达**（未获取=灰 `·`／已获取=绿 `●`），TTY 靠颜色、非 TTY 靠符号；
**节点与阶段名上都不写「已获取/未获取」文字**。

两条承重约束，改动输出时**必须**遵守：

1. **`echo` 输出汇**：终端没有「固定表头 + 下方滚动日志」这回事 —— 表头一旦被下方
   输出顶上去，按行数回退就会插进别人的行里。所以 banner **独占自己那块区域**，
   它下方的一切输出都必须走 `Banner.echo`。`save_refdata` / `save_kline_tdx` /
   `save_xdxr_tdx` / `save_stock_adj` 因此都新增 `echo=` 形参（默认 `print`）。
2. **tqdm 条必须 `leave=False`**（`fetch_stock_info` / akshare financial / kline 的
   逐 code 条）—— 条留在屏上，光标就不在 banner 之下，重画必然错位。

配套新增 `on_progress` 回调（`save_refdata` / `save_kline_tdx`），全部默认 `None`，
除 `--save` 外无调用方受影响。
