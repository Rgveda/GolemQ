# D46. `--sub tencent` 的 L1 走**拉取全市场**，**不改"全推"** —— 2026-10-15

- **编号**：D46
- **日期**：2026-10-15
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D46 DECISIONS.md`，或直接开这个文件

**背景**（用户）：「我记得它有一个白名单收取机制，名单高达五千个代码，但是大部分 L1
行情实现应该是市场全推模式才对，帮评估能不能改为全推模式。」

### 一、结论先说

* **那不是白名单，是全市场码表** —— 现状**已经是全市场收取**（实测一轮快照取到 4,936 条）。
  "改为全市场"没有可改的。
* **"全推"（服务器主动推送）在本源上做不到**：腾讯 `qt.gtimg.cn/q=` 是 HTTP 请求/响应，
  没有推送通道。全树唯一的真·推送是 `_l2_rows_from_qmt` 的 `xtdata.subscribe_quote`，
  而 MiniQMT 2026-10-01 停服（D10 / D13）。
* ⇒ **维持拉取，把参数修对**（见下）。要真·全推只有券商 L1（XTP/恒生等）开户接 SDK。

### 二、审出的两处**纯浪费**（⚠️ **本次未改**，等所有者点头）

| # | 问题 | 实测证据 | 改后 |
|:--|:--|:--|:--|
| ① | 每轮 `market_snapshot` 调**两次**（`sub_l1_from_tencent:301-309`，注释说第二遍「包含上证指数信息」）| 逐字复刻两遍：**合计 symbol 数 4,936 = 单遍**，`000001` 只出 `000001.XSHE`（平安银行），**无 `000001.XSHG`**。`formater_l1_ticks` 按归一化 code 去重 ⇒ **第二遍贡献 0 行** | 每轮省一半请求 |
| ② | `Tencent.max_num = 60`（`easyquotation/tencent.py:13`）把基类的 **800** 覆盖死了 | 实测：`k=800` → HTTP 200 / 800 条报价；`k=1000` → **HTTP 414 URI Too Long**。全量 87 页 → **7 页**，0.32s → 0.18s | 12.4× |

合计 **174 请求/轮 → 7**（24.9×）。按 09:15–15:15、2 秒一轮（≈10,800 轮/日）≈
**188 万次/日 → 7.6 万次/日**。顺带：现在一轮只花 0.54s / 2s 预算，
**性能上还没爆** —— 改它主要是请求量与礼貌性，不是救火。

`_l2_rows_from_tencent` 的 `for prefix in (True, False)` 是**同一处**毛病
（它自己的 docstring 甚至写着"**一次** `market_snapshot`"）。

### 三、ETF / 指数**能不能进 L1 tick 流**（用户追问）

腾讯**供得了**，但**现在一个都没进流**（码表里只有股票）。逐项实测：

| 族 | 腾讯供不供 | 实测 | 怎么取 |
|:--|:--|:--|:--|
| **ETF**（`etf_list` **1,696** 只） | ✅ **供** | 前 200 只 → **200/200** 有效（`v_sz158000="51~港股通金融ETF鹏华…"`）| `get_stock_type('158000')='sz'`、`('510300')='sh'` **恰好都对**，加前缀即可 |
| **真指数**（`sh000001` / `sz399001` / `sz399006` / `sh000300`）| ✅ **供** | 四条全通，`v_sh000001="1~上证指数~…"` | ⚠️ **必须显式带交易所前缀**，见下 |
| **通达信自编指数**（`880xxx`）| ❌ **不供** | `v_pv_none_match="1"` | `index_list` 1,291 只里 **689 只是它**（53%），取不到 |

**解析层是通的**：指数与 ETF 响应都 **53 个字段**（`format_response_data` 的门槛是 `>49`），
走 `q.real([...])` 全部解析成功，`formater_l1_tick` 归一化结果也正确
（`000001` → `000001.XSHG`，靠 `now` 启发式把上证指数与平安银行分开）。

⚠️ **两个坑，进流前必须先解决**：

1. **裸码会静默取错标的**：`index_list` 存的 `000001` 是**上证指数**，
   而 `get_stock_type('000001')` 判 `sz` ⇒ 取回**平安银行**。
   指数**只有带 `sh`/`sz` 前缀**才取得对，码表里必须存前缀形式。
   （同一个坑在 `refdata_save._supplement_stock_list` 的注释里已经踩过一次。）
2. **`normalize_code` 不认一部分 ETF 新号段**：实测 `158000` 报
   `normalize_code(): 6 158000` 并**原样返回裸 6 位**，而 `_write_ts_rows` 要求
   带后缀形式（裸码会让 L1/L2 两条流在同一 `(station, code)` 上错配）。

**未做**：把 ETF/指数并进码表是**另一个决定**（要考虑：ETF 一天多 1,696 只 × 每 2 秒、
指数该不该走 `source='tencent_l1'` 还是另立、`880xxx` 那 689 只怎么办）。
本次只做 D45（`stock_list` → 码表），不顺手扩大。

> ✅ **当天晚些时候已落地**：用户定「ETF / 指数要进 L1 tick 流」→ **D48**。
> 码表扩成 `stock ∪ etf ∪ index`（7,878 只）、**一律带交易所前缀**
> （不带前缀会把上证指数静默取成平安银行）、`880xxx` 那 689 只实测腾讯**不供**故剔除。
> 上面那个 `source` 问题的答案是：**仍走 `tencent_l1`，不另立流**。
