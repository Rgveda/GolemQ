# D54. 统一因果 Review 管线（daily + zen_minor + coldstart 子集 + runtime）

- **编号**：D54
- **日期**：2026-10-19
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D54 DECISIONS.md`，或直接开这个文件

**决定**：把 4.4 分散的几条复盘入口合并成**一套逐 Bar 因果管线**，放 `pipeline/review/`，
共用 `pipeline/base.py::BasePipeline`：

* `--review --daily`（兼容 `--review`）= **唯一落库路径**；
* `--review-runtime` / `compute_runtime()` = **内存计算，零 DB 写**；
* `scripts`/模型层要重特征时读最近一次 `--daily` 的落库行。

**入口拆分（4.4 的真实链路）**

| 老入口 | 产出 |
|:--|:--|
| `--review --daily` | 只写日族 `*_reality_feat_day` |
| `--review --reality` / `calc_zen_wavelet_reality` | 60min 特征（含 `zDLagMinR/zPLagMinR`），写 `stock_reality_features` 与 `stock_metadata(revision='zw_reality')` |
| 默认 `--review` / compact | 另跑 coldstart，写 `*_coldstart_reviews` |

**关键取舍**

1. **“分库” = 分表**：按 `is_stock_cn(code)` 逐码路由到
   `stock_/etf_/index_reality_feat_{day,60min,15min}`；ETF 是一等类型（D51），
   不新建 MongoDB 数据库，也不再把 ETF 当 `index_*`。
2. **老 `stock_reality_features` 的尺度是 60min**（实测时间戳
   `10:30/11:30/14:00/15:00`），命名缺频率后缀 ⇒ 并入 `*_reality_feat_60min`，
   旧名映射 `ZEN_DASH_LAG→zDLagR`、`M9T→m9t` 等；不保留无后缀旧表。
3. **KlineAnalyze 0.53 剔除**：`analysis/zen.py` 用新树 czsc 0.7.10 的 `bi_list`，
   只抽出老树 ~60 行的线段算法（`get_potential_xd` + `_update_xd_list`）。
4. **因果/前缀稳定**：所有 step 经 `slice_asof`；重档用固定窗口
   （日 1008 / 周 2160 / 60·15min 2016 / regtree 450），轻档用固定锚点
   （日 2016-01-01 / 15min 2017-01-01）。**水位只决定写哪些行，不改输入窗口**。
5. **列契约**：只保留消费方实际读取的列 + zen_minor 中间列；老树 136 列中的
   东财/同花顺/资金流/massive/CVaR/RENKO/MAXFACTOR 等死列不进库。
6. **coldstart 最小集**：`STAGE / BOOTSTRAP / M9T(raw+major) / POLY9(_NORM)_MAJOR /
   Prophet`；**不含**东财、同花顺、massive 先验。**不单独写 `*_coldstart_reviews`**
   —— 全部合并进 `*_reality_feat_60min`（用户 2026-10-19 定；同一张 60min 快照表，
   避免两套真相）。`m9tBsl/_m9tBslLag` 待 compact 特征链搬完再补。
7. **写口**：全部经 `datasource.writer.upsert_fields`；review 调
   `save_reality_feat(write_nulls=True)`，重算修正后能清旧值；CV 迁移默认不变。
   **库句柄走参数注入**：pipeline/CLI 不拼库名，从 `get_active_market().GOLEMQ_STOCK_CN`
   取实例，再作为 `db=` 传给 `save_reality_feat` / `fetch_reality_feat` /
   `get_watermark` / `set_watermark`（CLAUDE.md「库名不外泄」）。
8. **价格导出的列存比值**（D49 通则）：`poly9MajR` / `poly9WekR` / `rTrePrcMajR`
   是**拟合线 ÷ 同一行 close**；`rTreSlopMajR` 是**斜率 ÷ close**（相对收益/bar）；
   `poly9Nor*` 的 mapower 输入也改成 `poly9/close`。Prophet 的 `LB/UB` 本来就是
   `yhat/close`（D53）。避免复权换挡时整列断层。
   **读取是双向的**：`reality_save.restore_price_columns` / `fetch_reality_feat`
   （`restore_price=None` 自动检测）把比值列乘回同一行 close；runtime 默认
   `restore_price=True`。`*Nor*` 是归一化强度，**不还原**。

**与老树的已知差异（设计变更，不是回归）**

* `zDLag*` / `zPLag*`：czsc 0.7.10 vs KlineAnalyze 0.53，抽样差 ±1 根；
* `m9tLagWekR`：老树在**批次新增的日行**上算 event-lag，结果依赖批次窗口
  （同一 T 可差 900+）；新实现改在周线帧上算，因果且前缀稳定，差 ≤2；
* minor 累计计数器（`MsLeadinx3/x5`、`4QPwrlnLedInBf`）：老树 prefetch 起点随批次变化，
  绝对值不可复现；新实现固定锚点，事件/重置点语义一致；
* `STAGE` checkpoint：老树用 BOLL-HMA5 checkout 链，尚未搬；新实现用每 21 个交易日
  的稀疏 checkpoint（+ 最后一行），KMeans `random_state=0` 保证可复现；
* Prophet 落**比值**（D53），净空公式按比值改写；老树是绝对价。

**旧树 bug 清单（Phase 0 现场确认，修/不修按用户逐条拍板）**

   新实现**照搬**以对拍，是否修待定；
4. `calc_daily_features` 对 `persistence_features` 的空赋值；
5. `calc_zen_wavelet_reality` 用 `dropna` 推「缺失」⇒ NaN 行永远重算；
6. `calc_reality_features` 在 `len(ret_fooo_hour) <= 1000` 时静默不保存；
7. `GQ_save_daily_metadata_reality` 的 `created_at` 墙钟当 UTC（已在 `reality_save` 修）；
8. 4.4 `is_index_like` 把 ETF 路由到 `index_*`（D51 已修）；
9. `calc_bs_signals` 就地修改调用方 OHLC 帧（新实现纯函数）；
