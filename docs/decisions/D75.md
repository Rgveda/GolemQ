# D75. 4.4 旧 review 特征表不搬（未归一化 / 复权锚已冻结，无参考意义）

- **编号**：D75
- **日期**：2026-10-28
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D75`，或直接开这个文件

**背景**：2026-10-28 数据审计发现，4.4 的 `golemq.stock_reality_feat_*`
（旧 review 特征）比 8.3 的历史更长 —— 例如 000001 的
`stock_reality_feat_60min`：4.4 从 **2021-10-13** 起（4,891 行），
8.3 的新 review 行从 2024-08-13 起（2,128 行）。当时问「要不要把这批旧特征
补搬进 8.3」。

## 一、用户决定（2026-10-28）

> **不要做。旧表不是归一化数据，目前正在统一复权和归一化计算，
> 旧数据冻结股权价格在过去时间中，已经无参考意义。**

## 二、理由

1. **旧表不是归一化数据**：绝对价位、复权因子与当前口径不一致；
   项目从 **D70** 起统一「价格量纲列一律存 ÷close 比值 / `_DUMMY`」，
   旧表没有这套口径。
2. **复权锚被冻结在过去**：qfq/hfq 的基准日固定，当时算出的价格与今天
   重算的结果不可比（「冻结股权价格在过去时间」）。
3. **现在的方向是统一重算**，不是兼容旧值：宁可留缺口，也不要把两套
   复权口径的历史混进同一条序列。

## 三、边界

* **不搬**：4.4 `golemq.stock_reality_feat_{day,60min,15min}` 的任何特征列。
* **已搬的 CV 列保留**（D51）：那批只搬 `ClsMaj/ClsMin/Class` 等 CV 检出与
  `ChartScaned` 标记，属于**事件型稀疏数据**，不涉及价格归一化。
* 8.3 的 review 特征历史**只由新管线产生**；更早的缺口是**刻意的**，
  不是待补任务。
* `ZenPivotCnt` / `se` 等由**原始 60min/日线行情**重算（D74），
  与 4.4 旧特征无关。

## 四、验证

* 无代码改动；`docs/data_inventory.md` §四.4 已改成「明确不搬（D75）」。
* 不新增迁移工具，不扩展 `migrate_reality_feat_from44`（它仍只搬 CV 列）。
