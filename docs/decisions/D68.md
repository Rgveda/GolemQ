- **编号**：D68
- **日期**：2026-10-27
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D68`，或直接开这个文件

> ⚠️ **D74 起列位置变了**：`se` / `ZenPivotCnt` 已移到**日族**，
> attach 不再做 60min 精确 join（改随 `_attach_day` 因果映射）。
> 本文「只读 review 落库值、不在 notebook 重算」的原则不变。

**背景**：`calc_compact_pivot_feats.ipynb` 曾在 notebook 里用
`causal_pivot_count(pivots, dates)` 重新算中枢计数，得到 **1 → 2 → 3 → 4**；
而 review 的 `zen_snapshots` step 早已用**更长窗口**算好并落库
`stock_reality_feat_60min.ZenPivotCnt`（000711 实测为 **5**）。两套算法/窗口
不同，notebook 的结果与库不一致 —— 用户 2026-10-27 明确：

> 已经实现的算法、已经落库的算法，都不应该在 notebook 中重新计算，存在误差。

## 一、改动

* `analysis/reality_attach.py` 增加 `HOUR_EXTRA_COLUMNS`（`se` / `ZenPivotCnt`）
  的**精确 60min join**（`loaded['60min_extra']`）；
* notebook：
  - 删除本地 `causal_pivot_count` / 中枢计数表 / 样品熵重算；
  - `pivot-count` 直接画 `f['ZenPivotCnt']`（review 落库值）；
  - `plot-indicators` 增加 `se`（样品熵）面板；
  - `czsc` / `calc_pivots` 只保留在 K 线图 cell 内，**仅用于画箱体/笔**
    （review 未落库中枢几何），并在注释中写明“不是特征计算”。

## 二、覆盖度

`ZenPivotCnt` / `se` 是 review 后来新增的列，**历史行不一定有**。000711 实测：

```
有 ZenPivotCnt 的行 = 15 / 2,059（2026-10-20 ~ 10-23）
first = 5  (≥ 3)
```

notebook 不再用本地计算去“补历史”，只显示库里有的行，并打印：

```
⚠️ 只有 15/1920 行有 ZenPivotCnt（review 未回填本窗口的历史行；需 review --force/--from）
```

补历史应在 review 侧做（`--force` / `--from`），不在 notebook 里算。

## 三、边界

* 中枢**箱体/笔**的几何 review 没有落库；`plot-pivots` 仍在本地用
  `analysis.pivot.calc_pivots` 画图。这是**可视化**，不产出特征；若要求箱体与
  review 完全一致，需要 review 落库几何（当前未做）；
* `DEA_NORM_WEK` 仍由日线 → 周线现算（新 review 契约没有这列）；
  `Prophet` 连续量的 ffill 只是缺口填充，不改变已有值；
* **不再在 attach/notebook 里现算 coldstart/day**：review 没写的当日行保持 NaN，
  需在 review 侧补齐（原先的 `coldstart_fallback` 已删除）。
