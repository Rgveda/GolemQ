# D41. 字段常量的**值**用驼峰（≤16 字符，少数 18 容忍）—— 且**只改未入库的** —— 2026-10-12

- **编号**：D41
- **日期**：2026-10-12
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D41 DECISIONS.md`，或直接开这个文件

**背景**：用户要求「检查字段常量设定，`_` 连接的命名风格都变成驼峰（跟已有的风格相同），
尽量缩写到 10~16 字符以内，记住不要重名」。

**决定**：

1. **只动「没写进 8.3、纯计算」的那批** —— 单单词 / 无 `_` 的**不动**；
   `MARKET_TYPE` / `EVENT_TYPE` / `MARKET_EVENT` / `FREQUENCE` 这些**不是字段常量**，也不动。
2. **值是 MongoDB 字段名 ⇒ 在库的绝对不许改。** 唯一例外 `AKA.LAST_CLOSE = 'last_close'`：
   它住在 `golemq_stock_cn.etf_list` 里（由 `datasource/akshare_source.py:55` 的
   `'昨收': 'last_close'` **字面量**写入）。**保持 `'last_close'` 才是对的** ——
   改了常量、库里的字段名没变，那个常量就变成**撒谎的常量**（比不改更坏）。
3. **同值不算「重名」。** `AKA.CLOSE` 与 `FIELD.CLOSE` 都 `'close'`，是「同指一字段」的
   别名对，树里**原本就有 11 组**；`FIELD.PCT_CHANGE` / `FIELD.TRADE_CAL` 改成驼峰后
   与同名 `AKA.*` 同值，属这一类，**预期**。
4. 长度：目标 ≤16；**门槛是「>16 字符的占比 < 5%（每 100 个少于 5 个）」**（用户 2026-10-12）。
   实测现状：**341 个字段常量里 2 个 >16 = 0.59%** ✓ —— 即
   `MAS 'mCeptMacdCpdRtoMed'` / `'mMacdCpdBandRtoMed'`（各 18）。二者都**无 `_`**，
   本就不在「snake→camel」的范围内，**留着不缩**。
   （长度分布：8–12 字符最集中，2–16 连续分布。）

**改之前的三道查（缺一不可，都是实测）**：

| 查 | 怎么做 | 本次结果 |
|:--|:--|:--|
| ① 老值是否**已在 8.3** | 扫三库全部集合的字段名并集（**时序集合按 `listCollections` 的 `timeseries` 选项识别**，各抽 1 条；普通集合抽 ≤1000 条 —— ⚠️ 不能用 `estimated_document_count` 判大小，**时序集合数的是桶不是文档**） | 仅 `last_close` |
| ② 新名是否**与别的常量撞车** | 全部常量值建索引查重 | 2 条（见决定 3） |
| ③ 老值是否**被硬编码在别处** | `git grep "'<老值>'"` 排除常量定义文件 | **0** |

**落地**：`ee3eace` —— 111 条（`core/constants.py` 101 + `models/{alias,massive,risk}.py` 10），
只改**右值字面量**、左名不动 ⇒ 所有消费方自动跟随。全量 600 通过 / 0 失败。

⚠️ **今后加/改这类常量照此办理**：先三查、再改；**在库的一律不改**。
