# D29. 读路径接通 **REALTIME**：`_v3` / `get_kline_price_min` 的 `realtime` **不再是空转**

- **编号**：D29
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D29 DECISIONS.md`，或直接开这个文件

**起因**（用户 2026-10-09）：「我要做分析了，取行情，**8.3库，带REALTIME**」
「功能实现要跟 `_v3` 一样」「**而且还要比查询 `_v3` 快**」。

**讨论结论：不用搬 `get_kline_price_v8`。**

* 那个名字**两棵树都不存在**（只有老树 `GolemQ_old/scribe/min_migrate83.py` 的
  `get_kline_price_min_v8`，是 4.4→8.3 迁移脚本的读口）。
* 它的**能力已经在新树里**：`kline83._read_timeseries`（8.3 + **`ts` 索引** + `end` 补
  `23:59:59` + `start` 省略回看 `default_days` + `limit` + `code[:6]` 截断 + `vol→volume`）。
  老树那几段注释的措辞在新树里逐条都在 —— 重写时吃进去了。
* **`_v8` 这个后缀在新树没有意义**：老树用它区分「读哪个库」（4.4 vs 8.3），而 D12 已把
  4.4 铲掉 ⇒ 只剩一个库，后缀失去区分对象。

**真正缺的只有一样：`realtime` 形参是空转的**（旧 docstring 明说「不做实时补数，
保留参数只为签名兼容」）。故**就地接通**，不新增函数：

| 落点 | 做法 |
|:--|:--|
| `kline83._merge_realtime`（新）| 两道门（见下）+ 按频率调对应合并器 |
| `get_kline_price_min(..., realtime=True)` | 复权之后 → `GQ_fetch_stock_min_realtime_adv` |
| `get_kline_price_v3(..., realtime=True)` | 复权之后 → `GQ_fetch_stock_day_realtime_adv` |

**两道门**（都是为了「不需要补数时**不比 `_v3` 慢**」）：
1. **实时集合不存在就直接返回** —— ⚠️ `realtime_ts_collection` 是 `create_collection`
   包了 `try`，**读它会把不存在的集合建出来**（读路径的写副作用）；一次
   `list_collection_names()`（~1ms）挡掉，顺带省掉整条 tick 读。
2. 合并器**自带判据**（历史最后一根落后最后交易日 >10h（盘中）/ >40h（盘前）才读 tick）。

**实测**（300 只 × 1 年日线）：
```
realtime=False  1.211s   |   realtime=True  1.209s   |   差 -0.003s（噪声内）
读一次之后实时库集合数不变（✓ 读路径没有建集合）
```
**⇒ 带 REALTIME 的代价是 0。**

**顺带修掉一处实现与契约不一致**：`kline83.get_kline_price_v3` 的默认写 `None`，
而 `base_market.py` 的抽象声明与两个门面**一直写 `True`** —— 以前那个形参空转所以看不出来。
改成 `True`，且**行为保持**（门面一直显式传 `True`）。有用例钉住四个签名必须一致。

**关于「比 `_v3` 快」的诚实结论**：**同功能下没有更多水分可挤。** 实测 500 只 × 1 年
（12 万行）= **2.384s**，其中「Mongo 查询 + DataFrame 构造」**1.274s（53%）**、
「复权 + 形状适配」**1.110s（47%）** —— 查询已走 `ts` 索引、复权**已按区间查因子**
（不是全历史）。要大改只能动默认：跳过复权（省 ~47%）或投影掉列（**会改返回列**，
下游 `date`/`time_stamp` 会读）—— **那就不再「跟 `_v3` 一样」**，需另议。

⚠️ **实测边界**：本机 `golemq_stock_cn_realtime` 现在是**空的**（`--sub` 未跑过），
所以目前只验到「门挡掉、结果不变、耗时不增」；**tick 合成那一半要等实时库有数据才能验**。
