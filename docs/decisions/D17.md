# D17. `cli/__main__.py` 拆成「命令模块 + 有序注册表」

- **编号**：D17
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D17 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：`cli/__main__.py` 从 **742 行 / 16 条 `elif`** 收成
**99 行**（只负责：建 parser、注册全局开关、按序分发、没命中打 help）。
每条命令住 `cli/commands/<name>.py`，只暴露三件东西：

```python
FLAGS           # 命中哪几个 args 属性就归它
add_arguments   # f(parser)，把这个命令的参数注册上去
run             # f(args) -> int | None（**校验 + 委托**），返回值当退出码
```

`cli/commands/__init__.py` 里一张**显式有序列表**决定分发顺序。

**为什么不用 argparse 子命令（`golemQ save tdx`）**：那会改掉 `CLAUDE.md` /
`HANDOFF.md` / D11/D14/D15/D16 里**每一条已记录的命令**，也会打断老脚本；
而它这次的收益（更细的命名空间）是虚的。注册表留了后路 —— 将来要子命令，
挂个 `add_subparsers` 前端即可，**handler 一行不动**。

**为什么顺序必须显式**：老链里「两个开关同时给时谁赢」藏在 `elif` 的**书写顺序**里
（`PITFALLS.md` P12 记过同一个坑）。现在它是那张列表，且有测试钉住最要命的一条：
**`--save-coverage` 必须在 `--save` 之前**（`--save tdx --save-coverage` 两个都给时选前者）。

**验证方式（证明「没变」）**：改造前后对 6 条命令的 stdout+stderr+exit code
**逐字对拍**。**拆分当时六条全部一致**；包了对拍的命令是 `--save x` / `--save tdxx` /
`--save qmt` / `--sub <不存在>` / `--eneloop-list` / `--save-status`。

⚠️ **拆完后有两处刻意改动，对拍结论只对剩余的生效**：

1. **`--help` 里选项的排列顺序** —— 以前按老链 `add_argument` 的书写顺序（各命令的
   开关**交错**），现在按**命令分组**。实测选项集合**一个没多、一个没少**（38 → 38）。
2. **`--save` 的取值校验改由 argparse 的 `choices=` 负责**（用户 2026-10-09，
   见下条 D18）→ `--save x` / `--save tdxx` 现在是标准 usage + `invalid choice`
   + **退出码 2**，不再是手写的「错误: …」+ 退出码 1。

所以现在逐字一致的只剩四条：`--save qmt` / `--sub <不存在>` / `--eneloop-list` /
`--save-status`。**改动 1、2 都是有意为之，不是回归。**
