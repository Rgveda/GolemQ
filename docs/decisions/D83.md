# D83. 4.4 旧库只允许 `tools/` 访问；`GolemQ/` 与 `examples/` 完全解耦

- **编号**：D83
- **日期**：2026-11-18
- **触发**：用户「检查文档和 4.4，除了 tools 类脚本，其他代码需要完全跟 4.4 旧库解耦」。
- **代码**：`tools/migrate44.py`（原 `GolemQ/core/migrate44.py`）、
  `GolemQ/cli/commands/migrate.py`（只剩 8.3→8.3 合并）、
  `GolemQ/test_cases/test_no_44_runtime.py`（守卫）

## 规则

1. **4.4 通道只在 `tools/`**：`tools/migrate44.py` 提供 `mongo44_uri` /
   `client44` / `db44`；`GolemQ/`、`examples/` 不得 import，也不得自行连 4.4。
2. **运行时的一次性搬运函数删除**（它们都直接 `db44`）：
   * `metadata_save.save_turnover`（换手率，4.4 `stock_ranking` / `stock_valuation`）；
   * `reality_save.migrate_reality_feat_from44` / `verify_reality_feat_migration`
     （CV 存量）；
   * `refdata_save.save_index_list_from44`（指数名单补缺）。
3. **CLI 同步收口**：`--migrate-turnover` / `--migrate-index-list` /
   `--migrate-reality-feat` 从 `cli/commands/` 删除；只保留
   `--migrate-metadata-merge`（**8.3 → 8.3**，不连 4.4）。
4. **守卫**：`test_cases/test_no_44_runtime.py` 用 **AST** 扫描
   `GolemQ/` + `examples/`，禁止 `migrate44` 导入与 `db44` / `client44` /
   `mongo44_uri` 标识符。文档字符串里写 4.4 历史说明**不算违规**。
5. **`stage` 不再依赖 4.4**：按 D81 更正改为**移植 4.4 旧树的算法**
   （`analysis/stages.py::calc_cluster_checkpoints` / `calc_stage_frame`），
   `tools/migrate_stage_from44.py` 仅作对拍/校验。

## 事实（2026-11-18 实测）

* 4.4 `golemq.stock_ta_reviews` **仍在更新**：最新 `datetime` =
  2026-11-17 15:00，11-14 以来 36,650 行全部有 `STAGE`。
  所以 8.3 的 `stage` 断供不是 4.4 停了，而是新树当时没有生产者。
* 8.3 `stage` 非空行数：11-11 15,694 → 11-12/13 6,543 → 11-16 241 → 11-17 0。
  算法移植后由 review 重新产出。

## 不做的事

* **不清理已搬进 8.3 的 4.4 数据**（历史 `stage` / CV 列等）—— 它们已是 8.3 存量，
  与「运行时不连 4.4」是两件事。
* **不复活 `GQ_MIGRATE44_URI` 环境变量**：地址仍只从 `config.ini` 的
  `[MONGODB44] uri` 读。
