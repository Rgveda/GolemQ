# D47. 删除 L2 流：腾讯 L2 **整条撤掉**，QMT 五档占位一并删

- **编号**：D47
- **日期**：2026-10-15
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D47 DECISIONS.md`，或直接开这个文件

**背景**（用户）：「L2 那条流不要留」。追加定的：「**连 QMT 占位一起删**」。

---

## 一、先算清代价：**删它对数据是零损失**

这不是权衡，是核对。两条实测：

| | 结论 | 依据 |
|:--|:--|:--|
| **字段** | L2 是 L1 的**真子集** | `_l2_rows_from_tencent` 只取 `L2_DEPTH_FIELDS`（bid/ask 1-5 × 价/量）+ `L2_EXTRA_FIELDS`（涨停价/跌停价/均价/委差/量比）；而 L1 走 `formater_l1_tick` 把**整份快照**落库，这些字段本来就在里面 |
| **节奏** | L2 **比 L1 还慢** | L1 `sleep_time = 2.0`，L2 `sleep_time = 3.0` |

⇒ 旧的 L2 流**既不多个字段、也不快** —— 它就是**同一份 HTTP 响应**（`market_snapshot`）
按 3 秒又落了一遍。删掉不损失任何信息。

⚠️ **这条核对必须做在前面**：D10 当年的原话是「这份重复是**刻意保留**的 ——
它是 3 秒节奏的独立流，也是**将来接替代源的位置**」。若只照那句话办事就会以为
删它会丢东西。**实际是两个字段子集 + 一个更慢的节奏。**

## 二、决定

**删**（`markets/StockCN/realtime.py`）：

* `sub_l2_from_tencent()` —— 订阅器本体
* `_l2_rows_from_tencent()`、`_l2_row()`
* `_l2_rows_from_qmt()`、`_l2_qmt_xt_codes()` —— **QMT 五档占位**
* `L2_DEPTH_FIELDS`、`L2_EXTRA_FIELDS`
* `REALTIME_SOURCE_TENCENT_L2`、`REALTIME_SOURCE_QMT`、`QMT_REALTIME_ENABLED`
* `import threading`（唯一用处是那条后台订阅线程）

**连带**：`markets/StockCN/__init__.py` 的 `register_subscriber('l2_tencent', …)`
与 `__all__` 条目；`--sub l2_tencent` 的 CLI 文档；`GQSUBSCRIBER` 回到
`l1_tencent` / `tencent` 两个键。

### ⚠️ 这一条**推翻 D10 的一段与 D13 的一部分**

| 原决定 | 原话 | 现在 |
|:--|:--|:--|
| D10 | 「L2 那份重复是**刻意保留**的……也是将来接替代源的位置」 | **作废**：重复是自证的子集，没有保留价值 |
| D13 | 「QMT 那条路**只保留结构**」（`QMT_REALTIME_ENABLED=False`） | **作废**：它保留的正是 L2 的取数函数；L2 没了，「把开关改回 True」就无处可读 |

**代价照实说**：将来接替代源（cfquant）要走**新增**，不是「把开关改回来」。
D13 的「只留结构」本意是留个接口，但那个接口是**挂在 L2 上**的 —— 子集流先没了，
占位也就成了纯死码。

## 三、**保住**的东西（别跟着一起删）

`source` 字段与它的去重键纪律**一个字不动**：

* 库里存量行已经带 `source: 'tencent_l1'`，读取器（`GQ_fetch_stock_realtime_adv`
  的 `source=` 形参）按它过滤 —— **删掉所有历史行都读不出来**；
* `_write_ts_rows` 的删除条件仍按 `source` 分组，`last_ts` 的键仍是 `(source, code)`。

⚠️ **删了 L2 ≠ 这条纪律作废。** 它是「**多条流可共用一张日集合**」这个**设计前提**
的承重条件，不是"当时恰好有两条流"的巧合。`test_realtime_store` 里那条
「同一个 code、同一个 ts，两条流互不遮挡」的用例已改用**合成** source 名
（`synthetic_second_stream`）继续钉着 —— 而不是跟着 L2 一起删掉。

## 四、被删代码里那几条**硬换来的坑**（知识留下，代码不留）

`_l2_rows_from_qmt` 是 MiniQMT 那条路的全部经验。它删了，但这几条**将来重写时必须重新踩**：

1. **必须先 `subscribe_quote(period='tick')`** —— 未订阅的代码 `get_full_tick`
   只返回**陈旧缓存**（实测盘口全 0、`time` 停在几分钟前），看起来像「盘口是空的」，
   实则是没订阅。这是那条路上唯一的坑。
2. **订阅是持续生效的** ⇒ 订阅一次即可，每轮重订阅反而**当轮必空**（订阅后立刻读拿不到）。
3. **本机 QMT 客户端不提供盘口深度**（2026-09-21 实测）：`get_full_tick` 的 bid/ask
   恒为 0，`get_fullspeed_orderbook` 直接报「当前客户端未支持此功能」，
   `get_l2_quote` 返回空。只有价格是活的。
4. **「深度全 0」与「这个源给不了」必须能区分** —— 旧实现写了 `depth='unavailable'`
   而不是写 5 个 0。写 0 会被读成「盘口是空的」。
5. **QMT 的 `time` 是 epoch 毫秒（UTC 基线）**，**不能**过 `bj_date`（会再 +8 小时）。

前 4 条在 `AUDIT` 层面已经由 `PITFALLS.md` 与本节承载；第 5 条是 `bj_date`
唯一入口那条纪律的实例。
