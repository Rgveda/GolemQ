# D25. K 线短路：**集合自证探针 + 逐只水位 + TTL 兜底**（三条缺一不可）

- **编号**：D25
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D25 DECISIONS.md`，或直接开这个文件

**背景**：全量 `--save pytdx` 每只 (code, 频率) 都要开一条 TDX 连接，即使数据早已最新。
实测单 code **0.2–0.34 s**（`new_api()` 建连+探活 0.244 s 占 **72%**，取一页 0.093 s），
4 worker ⇒ **12–20 code/s** —— 用户实跑最好 12+ code/s，**那就是满速**。要更快只能不建连。

**判据（三条同时成立才跳）**：

| # | 判据 | 出处 |
|:--|:--|:--|
| ① | **集合自证**：集合里有 `ts >= 活动阈值` 的 bar ⇒ 二分出**数据前沿** | `collection_frontier` |
| ② | **逐只水位**：该 code 最后一根 `ts >= 前沿` | `last_bar`（本来就查）|
| ③ | **TTL**：该集合上次**全量成功落库**未超时（盘中 5h / 盘后 24h） | `allow_shortcircuit` |

三条缺一不可：①②保证判据**偏向取数**，③防「所有人一起错」。

**用户 2026-10-09 定的两条硬口径**：
* **TTL 颗粒度细到每个节点**（26 条：# 参考数据 4 + K线 18 + 复权 4），不是按族、不是全局。
  落在既有签到表 `GOLEMQ.function_checkins`，键 `kline:<集合>` + `host:<主机名>`，
  **复用** `refdata_save` 那套（`stable_caller_key` / `checkin_age_hours` / `mark_checkin`
  已上移到 `supervisor.function_checkin`）—— 计时键只有一处真相。
* **记账口径 = 「这个集合上次**全查**于何时」** —— 短路过的那一遍**不记账**
  （记了 TTL 会被无限推后，兜底网永远不触发）。`--save-refresh` 与 `dry_run` 也不记。

**弃案**：「拿集合整体倒序取最新一根当基准」—— 实测 `find_one({}, sort=[('time_stamp',-1)])`
在 `stock_day` 要 **5.14 s**、`stock_1min` 直接超时。改成**二分探针**后每集合
**0.02–0.15 s**（9 次探针）。见 `PITFALLS.md` P25。

**为什么「活动阈值」按日历、而「前沿」按数据**：日历只在**日**级出场（今天开市了没 /
上个交易日是哪天），**不做**分钟级边界推演（半日市、14:57 竞价那些脆东西）。
⚠️ **盘中绝不退到昨天** —— 退了的后果见 P25。

**复权四节点本次只记账、不开闸** —— ⚠️ **当日即被推翻，见下面「追加」**。

（原）理由：前复权因子一有新事件就要**整条重标**，用 TTL 拦截意味着
「最多滞后一个 TTL 才发现今天除权」，那段时间 `to_qfq()` 拿的是旧基准。记账先落盘。

**追加（2026-10-09 同日晚，用户决定）**：`stock_xdxr` / `etf_xdxr` **开闸** ——
判据与 K 线同一套（`allow_shortcircuit` + `KLINE_TTL_HOURS` 的 `(5, 24)`）。

* **代价照实说**（上面那段依然成立，只是用户选择接受）：新除权事件最多**滞后一个 TTL**
  才被发现，那段窗口 `{tgt}_adj` 是**旧基准**，而前复权因子一有新事件就要**整条重标** ——
  即那段时间 `to_qfq()` 给出的是错的（**不报错**）。`--save-refresh` 可强制关掉闸。
  ⚠️ **但「滞后一个 TTL」是最坏账面值，不是实际风险**：除权除息是**日级**事件、且
  **开盘前就已确定**，所以够不够的判据是「**每个交易日至少扫过一次**」—— 而
  `(5, 24)`（盘中 5h 一次 + 盘后 24h 一次）**保证每交易日至少覆盖一次** ✓。
  真正的风险只剩最坏情形：**某个交易日从头到尾一次都没扫**（需连续 5h+ 不跑）。
* **`{tgt}_adj` 两个节点刻意不设闸**：它们不是"定期全扫"，而是"**事件变了才重算**"
  （只在 `events_changed` 非空时才走到）—— 拿 TTL 拦它等于**该重标的时候不重标**。
* ⚠️ **新增一条防静默丢数据的规则**：**只有全宇宙的跑法（`codes is None`）才记账**。
  复权的闸是**集合级**的，没有 K 线那样的逐 code 水位兜底 —— 一次
  `--save-codes 600519` 的小范围跑若也记账，就会把闸打开 ⇒ 之后**全量跑整段跳过
  xdxr** ⇒ 新除权事件静默漏掉。K 线那边同样加了这条条件（它有逐 code 兜底、本不需要，
  但**两边规则刻意一致**：别让试跑开闸）。

**顺带发现的一个既有机制**：`supervisor.function_checkin.checkin_function` 在
`expired_timestamp` 未到时**直接早退、不写**（`reason: expired_time_not_reached`）——
所以「在 TTL 窗口内重复记账」是**空操作**，无法刷新时间戳。对 TTL 语义是对的，
但也意味着上面那条新规则只在**集合头一次**被记账时才起作用。

**顺带修掉**：`_fetch_docs` 里 `tdx_market_of()`（**纯查表**）原先排在 `new_api()` 之后 ——
号段表没有的 code（指数 `810`/`899` 等）每频率**白建一条连接**再返回 `'empty'`。
已提到建连之前（正好命中用户观察到的 `index_*` 段）。

**实跑验证**（2026-10-09，`index_day` 两只票）：第 ① 遍建连 3 次 / 写 2 行；
**第 ② 遍建连 1 次（只剩开跑时的北交所探针）/ 写 0 行 / `skipped_fresh=2`**。
