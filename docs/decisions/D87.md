# D87. `stock_reality_feat_60min` 是**特征表**，允许插「只有特征列」的稀疏行

- **编号**：D87
- **日期**：2026-11-22
- **代码**：`tools/backfill_quad_pwrln_wek.py::_write_60min_synthetic`
- **测试**：`test_cases/tools/test_quad_pwrln_wek.py`

## 结论

`*_reality_feat_*` 是**特征表**，不是纯行情表。库里实测：`2021-11-23 15:00`
那一行只有 16 个字段 ——

```
ChartScaned, ClsMin, ConfidenceMin, CoordinatesMin, code, created_at,
date, date_stamp, datetime, garPAnchor, garPClr, garPCount, garPD, stage, time_stamp
```

**没有 close/open/high/low**。所以「给某天补一根只有 `4QPwrlnWek` 的 15:00 行」
不会污染行情数据，稀疏行本来就是这张表的常态。

⚠️ 我（AI）起初把它当纯 OHLCV 行情表，在交付时把「插稀疏行」标成高风险并
推迟执行 —— 判断错了。用户 2026-11-21 明确要求插这张表。

## 补行口径

* 只补 **该码自己那天有日线**（用它自己的日线日期，不用全市场交易日历），
  否则会把上市前的幽灵行插进去；
* 只补**该码当天没有任何 60min 行**的日期 —— 已有行只更新列，不新建；
* 唯一索引 `(code, time_stamp)`，写入走 `save_reality_feat(..., write_nulls=False)`；
* 行形状：`{code, datetime:'YYYY-MM-DD 15:00:00', date, date_stamp, time_stamp, 4QPwrlnWek}`。
