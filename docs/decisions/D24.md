# D24. 环境自检也挂 banner（四态）+ **硬拦口径**与**放行集合**

- **编号**：D24
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D24 DECISIONS.md`，或直接开这个文件

**背景**：`--save tdx` 有统一的状态 banner，而它前面那段环境自检只有逐行 `print` ——
结论要读文字才知道对不对。用户 2026-10-09 要求「bootstrap 也加一个 banner，
显示变化规则同 tdx 获取」，并给了检查子步骤。

**定的四件事**：

1. **同构**：复用 `core.presentation.Banner`，**一行平铺**
   `环境自检  操作系统 ●  python ●  依赖包 ●  线程环境 ●  CPU 架构 ●  CUDA ●  时区 ●`。
   节点顺序即屏上顺序（D17 的先例）。
2. **四态**：灰 `·` 未检查 / 绿 `●` 通过 / 黄 `●` 警告 / 红 `●` 失败。
   取数那三态（`PENDING/RUNNING/DONE`）**一个字不改** —— 两个 banner 从不同屏，
   且自检**不加**「检查中」态（毫秒级看不见，且绿 `RUNNING` 会与「通过」撞色两义）。
3. **硬拦只两项**：`python` 与 `依赖包`（`ENV_GATE_NODES`）。其余全黄/灰：
   OS / 线程环境 / CPU 架构 / CUDA / 时区 —— 它们可能是**不适用**（无 N 卡）
   或**显式选择**（你自己 export 了线程数），判红会误伤。
   ⚠️ **`REPAIR_COMMANDS` 四条放行**（setup / mongodb-init / dingtalk-init /
   serverchan-init）：拦掉它们等于「环境不对就永远修不回来」——
   与 D20 里「配置类命令绝不连库」同一个道理。**这是本次唯一偏离「用户只说了硬拦」的地方。**
4. **时间戳只盖静态头行**。⚠️ **2026-10-09 晚改版**（见 `DECISIONS.md` D27）：
   时刻戳**只在开头的身份块出现一次**（`GolemQ  [2026-10-09 17:29:39]`），
   两个 banner 一律 `header=False`，阶段行（`环境自检` / `数据源` / `参考数据` /
   `K线` / `复权`）跨它们对齐成一列 —— 原先两条 `[戳]: …` 紧挨着，用户口径「像同一
   件事说了两遍、眼花」。`Banner(header=True)` 仍是默认，直接调用方行为不变。
   状态行会随重画反复重写，盖上去只会让「变化规则」失真。

**MongoDB 不进 banner**（用户 2026-10-09 明示）—— `require_mongodb()` 在 banner
`close()` 之后单独跑，形状不变。

**新增的三个检查为什么值得**（都不是装饰）：

| 节点 | 依据 |
|:--|:--|
| `时区` | `kline_save.py:396-398` 用**裸 `datetime.now()`** 当北京时间判「收盘」——机器时区一偏，那个闸在错的时间开合且**不报错** |
| `CPU 架构` | 本机 18 核 **6P+12E**、**无超线程**（Ultra 5 250K Plus）。一旦将来按「逻辑核数」开 worker，会开到 12 颗 E-core 上（现在全树硬编码 `jobs=4`，故本项**不承重**，只作事实留存） |
| `线程环境` | 就是 P21 的真因 ①。⚠️ **顺带修了一个假绿**：`check_blas` 原先只看 `is None`，于是 `OPENBLAS_NUM_THREADS=4` 与「压根没设」后果几乎一样却报绿 —— 现在值不是 `1` 也报黄 |

**弃案**：把 MongoDB 并进 banner（用「未检查」灰点表示"这条命令不需要库"）——
用户否决；且那样会让配置类命令为了自检去连一次库，与 D20 的时机理由冲突。
