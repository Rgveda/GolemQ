## 二、落库存**比值**（与 `GAR_P` 同一条纪律）

```
prophetLb = yhat_lower / close     ← 同一个 bar
prophetUb = yhat_upper / close
prophetLbMaj / prophetUbMaj        ← 日线那一份，按**日期**对齐到任意频率
```

`1.0` = 与 close 持平；还原价 = `比值 × 当日 close`。

### ⚠️ 一条必须写清楚的边界：「不重算」才完全跟随

比值带来的是 **历史行不用重写**：除权后 `close` 整段按 k 缩放，
`比值 × 新 close` 自动跟着缩放。

但 **Prophet 本身不是尺度等变**的（`changepoint_prior_scale` 作用在 y 的**绝对增量**上）。
2026-10-18 实测（600519 日线，整窗 ×0.5 后除回去比较）：

| 量 | 最大相对差 |
|:--|--:|
| 比值 | **0.82%** |
| 绝对价 | **0.82%**（同量） |

⇒ 这 0.82% 是「**除权后要不要重算**」的差，**不是**存比值的缺陷。
别把它写成"数学不变"——`test_fbprophet.TestScaleBehaviour` 用**上界断言**钉着。

## 三、依赖升级：prophet 1.1.7 → **1.5.0**（必须）

`prophet 1.1.7` 在 **pandas 3.0** 上**连 `fit` 都跑不了**：

```
Prophet.fit → preprocess → make_all_seasonality_features
            → regressor_column_matrix → pd.crosstab(...)
            → ValueError: cannot reindex on an axis with duplicate labels
```

`pd.crosstab` 的内部语义在 pandas 3 变了（D52 同一波）。**升级到 1.5.0 解决**，
且 `pip install --dry-run` 确认**只装 prophet 一个包**，不动 numpy/pandas/torch。

## 三之二、⚠️ Prophet 的区间是**抽样**的 —— 必须固定种子

`mcmc_samples=0` 时，`yhat_lower` / `yhat_upper` 由 `np.random` 从后验近似里抽
`uncertainty_samples`（默认 1000）份取分位数 ⇒ **同一模型、同一份数据，连跑两次都不同**：

```
同一输入两次 predict，yhat_lower 最大差 0.22（约 2%）
```

⇒ 本模块在 `predict` 前 `np.random.seed(UNCERTAINTY_SEED)`（**跑完还原**全局 RNG）。
不固定的话每次重算都会给同一根 bar 写不同的区间，「重跑幂等」就是空话。

### 与老树逐值对拍（**已做**）

先把 `GolemQ_old/fractal/v9.py` 补上 `import pandas as pd`（该模块**从没 import 过**，
函数注解在导入期求值 ⇒ `NameError: pd`；`GolemQ_old/` 在 `.gitignore` 里，不影响仓库），
再把两个只喂 `CHANGE_POINT*` 的替身（`calc_feature_event_timing_lag` / `calc_energy` /
`calc_event_timing_lag`）换成零值，然后两侧用**同一个** `np.random.seed()`：

| 量 | 结果 |
|:--|:--|
| `LB`（转 float32 后） | **逐位相同** |
| `UB`（转 float32 后） | **逐位相同** |

差的那点（~8e-7）**只来自老树落库的 `astype(np.float32)`**，我们算 float64。
`test_fbprophet.TestMatchesOldTree` 把这条钉住了。
