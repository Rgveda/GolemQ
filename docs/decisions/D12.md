# D12. **把 QUANTAXIS 从全树剔除**（D9 的反面）

- **编号**：D12
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D12 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-08）：QUANTAXIS **彻底移出运行时代码**，验收标准是
`grep -rn "^ *from QUANTAXIS\|^ *import QUANTAXIS" GolemQ/` **零命中**。
5 个句柄的去向：

| 原符号 | 原指向 | 处置 |
|:--|:--|:--|
| `DATABASE` | 4.4 `golemq`（QUANTAXIS 配置驱动） | → **`GOLEMQ`** = 8.3 的 `golemq`（定义在 `core/settings.py`）|
| `DATABASE_QA` | 4.4 `quantaxis` | **删**（唯一消费者 `symbol._db()` 随死代码一起删，无需改绑）|
| `QAREALTIME` / `QASETTING` / `DATABASE_ASYNC` | — | **删**（实测零真实消费方）|
| `DATABASE_STOCK_CN` / `_REALTIME` | 8.3 | **改名** `GOLEMQ_STOCK_CN` / `GOLEMQ_STOCK_CN_REALTIME` |

**命名规则（用户定）：名字即库名** —— `GOLEMQ` / `GOLEMQ_STOCK_CN` /
`GOLEMQ_STOCK_CN_REALTIME`。`DATABASE_*` 那一族的信息量只有"哪个配置提供的"，
换库即失效。

**拒绝的方案：留着那一处 `import QUANTAXIS`，只把它改成惰性（= D9 + 本次的前半程）。**
理由：惰性只推迟了**加载**，没改变"库句柄由另一个框架的配置驱动"这个事实 ——
`sys.modules` 里照样会出现 QUANTAXIS 整棵树（实测 3,564 个模块里约 670 个是它带来的：
tushare / statsmodels / matplotlib / joblib），"解耦"就成了空话。
验收要求是**归零**，不是"看不见"。

**边界：解耦的对象是「业务框架」，不是「通用工具库」**（用户 2026-10-08 明确：
「解耦不用极端化，基础数据结构三家是可以用的」）。**pandas / numpy / polars 照用** ——
剔除 QUANTAXIS 的理由是它是**与本项目的业务强绑定**的运行时（配置驱动库句柄、
自带行情/撮合/数据表示），而这三家是通用工具，不用就得自己造轮子。
判据：**换掉它会不会让"数据怎么存、怎么算"这件事重新发明一遍**。
实测一例：文档构造改用 polars 列式后 51.5 µs/根 → 4.3 µs/根（全市场 1min 69 s → 5.8 s），
等价性由单测逐字段对拍（`test_kline_save` 的 `TestBarDocsMatchesRowWise`）。

**约束（新增，写进 `core/migrate44.py`）**：4.4 **只允许经那一个模块**读，且只允许
被 `--migrate-*` 这类一次性命令引用；**运行时代码禁止 import 它**。
地址用常量 + 环境变量（`GQ_MIGRATE44_URI` / `--migrate-source-uri`），
**不读 `~/.QUANTAXIS/`** —— 那正是被剔除的耦合。
