## 一、合并的**形状**：两张表本来就同形

| | `stock_metadata_day`（旧） | `stock_reality_feat_day`（新） |
|:--|:--|:--|
| 库 | `golemq_stock_cn` | 同 |
| 唯一键 | `(code, date_stamp)` | **同** |
| 唯一索引名 | `code_1_date_stamp_1` | **同** |
| 写口 | `writer.upsert_fields` | **同** |
| 实测行数（2026-10-16）| **17,133,065** | **1**（D42 的冒烟行）|

⇒ **合并不涉及文档结构调整** —— 把两个写口指向同一个集合名即可，再加一次存量搬运。

⚠️ **绝不能用 `save_collection`**（`ReplaceOne` 整文档替换）做这件事：目标表里已有
reality 特征列（`ClsMaj` / `ConfidenceMaj` / `CoordinatesMaj`），整文档替换会把它们
**静默抹掉**。这正是 `upsert_fields` 存在的理由（D34）。

## 二、集合名收敛到**唯一出处**，并把常量改名

### 改名：`METADATA_DAY_COLL` → `REALITY_FEAT_DAY_COLL`

值从 `'stock_metadata_day'` 变成 `'stock_reality_feat_day'` —— **常量名必须跟着改**。
一个叫 `METADATA_DAY_COLL` 却等于 `'stock_reality_feat_day'` 的常量就是
**撒谎的常量**，比不改更坏（D41 的同一课）。

### 值不再自己拼，取自 `reality_save.reality_feat_name`

```python
REALITY_FEAT_DAY_COLL = reality_feat_name('day', MARKET_TYPE.STOCK_CN)
```

那是 `*_reality_feat_*` **六族命名规则的唯一出处**（带 doctest）。
自己拼一份就是**两个真相源**，而分叉的症状是**静默写到另一张表**。

### 顺带收敛一处硬编码

`refdata.GQ_fetch_stock_metadata_day` 里**硬编码过** `'stock_metadata_day'` 字面量
（与常量并存 = 两个真相源）。已改为 import 常量。

## 三、合并函数的设计

`metadata_save.merge_metadata_into_feat(batch, limit, dry_run, verbose, echo)`

* **幂等**：只 `$set`、键 `(code, date_stamp)` ⇒ **重跑不会插重复行**，
  中途挂了直接再跑一遍，**不需要断点续传**。
* **`no_cursor_timeout=True`**：全量 1,700 万行要跑几十分钟，MongoDB 的游标默认
  10 分钟空闲超时会**在跑到一半时**把它掐掉。
* **只投影掉 `_id`**，其余字段**一个不改名、不换算** —— 这是"原样搬"。
* 缺 `(code, date_stamp)` 的行**丢弃并计数报出**（落进去会插出无键文档）。

### 只读核对：`verify_metadata_merge(sample)`

**合并跑完必须跑它再谈 drop** ——「搬完了」这句话得有依据。
抽样从**源表尾部**取（`$natural:-1`）：尾部是最近写入的、也是最可能被后搬覆盖的。
逐字段比，**浮点按位比**（搬家不该动任何一个 bit）。

CLI 侧：**不符就非零退出** —— 否则「核对过了」会被读成「核对通过」。

### ⚠️ 两条值得记的观察

**① 那 3 个 CV 列还在 —— 这**反过来证明**走的是 `upsert_fields`。**
若用了 `save_collection`（`ReplaceOne` 整文档替换），`ClsMaj` / `ConfidenceMaj` /
`CoordinatesMaj` 会被**静默抹掉**，而**对拍查不出来**（对拍只看源表有的字段）。

**② D42 那行冒烟数据现在"两组列同住"** —— `(600519, 2026-01-05)`：

```
ClsMaj: 'Buy'  ConfidenceMaj: 0.560  CoordinatesMaj: 1765382400000.0   ← D42 的 CV
TurnoverRate: 0.0021   turnover: 0.005666                              ← 刚搬来的元数据
```

这正是合并要的效果（一行 = 一标的 × 一交易日，两组列同住）。

⚠️ **副作用（已知、可接受）**：该文档的 `created_at` 被元数据那次写入**覆盖**了
（`upsert_fields` 只 `$set` 传进去的字段，而 `created_at` 在元数据行里）。
`created_at` 是记账字段、不是测量值，**没有丢任何观测数据**。
