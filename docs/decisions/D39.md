**背景**：用户要求继续搬运四量图与 6 个重要指标
（`QLevMACDLagD` / `ZenPivotLag` / `QuadBsTukLag` / `MsLeadinBf` / `MsLeadinx3Bf` / `MsLeadinx5Bf`），
约束是**「尽可能解耦，越少增加引用和管线越好」**。

**勘查结论（三条，都推翻了直觉）**：

1. **「四量图」不是图，是特征计算**。名字只活在老树 docstring 里；真身是
   `analysis/base.py:119` `calc_four_quadrant_boost`（~580 行 `np.where`）。
2. **6 个指标一个都没在新树**（3 个只有别名常量、3 个连常量都没有），
   而它们锚在的 4 个核函数（`Timeline_*` / `calc_event_timing_lag` / `calc_energy`）
   **早就搬好了** —— 在 `analysis/timing.py`（2026-10-10 随筹码分布搬回），
   **方案初稿误判为「要先补」**（漏看了那个文件）。
3. 四量图前 ~130 行是**数据修复序言**：`GQ_SU_remove_stock_min_adv(...)` 把疑似
   **停牌伪 0** 的 bar 从 `stock_min` **移走**到 `stock_min_removed` ——
   **一个破坏性 Mongo 写，藏在特征计算函数里**。

**决策（用户定）**：

* **丢掉那一段修复序言**。理由：新树**已经清过**这次
  （`maintenance.GQ_purge_suspended` 移走 3,908,747 行、`GQ_suspension_dates` 现返回 0）
  ⇒ 照搬是「破坏性写 + 常态 no-op」。**把「数据已清理」当既定前置条件，函数只做算术。**
  ⚠️ **行为差异**：老树在 `len(features) != len(ohlc_data)` 时**先修复再算**，
  这里直接算（长度不等由 numpy 广播/报错暴露，**不静默**）—— 已写进模块 docstring。
* **顺带搬 6 个 `BS_*` 的 `Timeline_duration` 包装**，否则 `QuadBsTukLag` 跑不出结果。
  ⚠️ 但它们的输入（`BS_BUY`/`BS_SELL`/`BS_STAR_UP`/`BS_STAR_DOWN` 及 `_MAJOR`）
  来自**星线检测链 `calc_bs_signals`，那条链未搬** ⇒ `calc_bs_before` 与
  `calc_quadrant_bs_trunk_timing_lag` **吃输入列，不能自称端到端可跑**（docstring 已注明）。
* **单模块 `analysis/quadrant.py`**，模块级只 import `numpy`/`pandas`/`talib`。

**解耦动作**：`QA.MARKET_TYPE` → `core.constants.MARKET_TYPE`；删 `import QUANTAXIS`
与 `from QUANTAXIS.QAUtil import DATABASE`；删 `from GolemQ.fractal.v0 import kdj_cross_func`
（实测该名在老树**只在 import 行出现、函数体从未调用**）。
**验收**：`import GolemQ.analysis.quadrant` 后 `sys.modules` 里**无 QUANTAXIS**（有测试钉住）。

**只搬一条（D35 纪律）**：四量图老树有 pandas / polars / notebook 三份 ⇒ **只搬 pandas**；
`QuadBsTukLag` 老树有三份副本 ⇒ **只搬 `quad_gear.py` 的规范版**。

**常量补齐（P1：只填真值）**：`models/alias.py` 的 `LTT` +33、**新建 `TRD` 类**（+2，
⚠️ 只补用到的那两条，**不是 TRD 搬完了**）；`core/constants.py` 的 `FIELD` +11、
`STATE` +1 —— 全部逐字取自老树 `models/alias.py` / `utils/parameter.py`。

**正确性证据**：`test_cases/test_quadrant.py` —— `calc_four_quadrant_boost`（含
