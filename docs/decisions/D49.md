## 三、**绝对价位改存比值**（用户提的原则 —— 本次最重要的一条）

**背景**（用户）：「`GARIDENT_PRICE` 以前是按价格落库 4.4 的……考虑到复权，落库后
不会随复权系数修正。我觉得不再落库记录价格，而是**记录与同一 bar close 的相对比值**
更合适。」

### 决定：`GAR_P` 落**比值**，并**新增一列锚日期**

### 为什么成立（三条**实测**，不是论证）

| 断言 | 实测 |
|:--|:--|
| 整窗乘常数 k ⇒ 带**等比例**缩放 | k=0.37/2.5/100 相对误差 **0.000e+00** |
| `STAGE` 对整窗缩放不变 | ✅ |
| 比值对**未来除权**不变 | ~1e-16（float64 机器精度）|

**为什么精确**：除权因子只在事件点跳变，而事件在**锚之后** ⇒ 锚 bar 及**整窗**被
**均匀**缩放 ⇒ 比值不变。

⚠️ **「不变」是数学意义，不是逐位相等。** 我一度写成「逐位不变」，那是**过度断言** ——
`(b*k)/(p*k)` 与 `b/p` 浮点上差 ~1e-16。这个错误**当场反噬了我自己的测试**（三条断言
写成 `array_equal`，三连假红）。**对拍/断言一律用 `allclose(rtol=1e-12)`。**

### ⚠️ 还原时乘**锚 bar** 的 close，**不是当前 bar** 的

用户原话是「close 会变复权价格，然后 `GARIDENT_PRICE` 也会跟随复权 close 变化」——
若理解成 **× 当前 bar 的 close**，`STAGE` 会**塌成常数**。实测：

```
A) 乘**锚**close  → 与原带最大绝对差 0.0        ✅
B) 乘**当前**close → 第-1/-60/-300 根全变 STAGE=0（原本 0/1/1） ✗
```

**原因**：`GAR_P` 是「最近一个 checkpoint 的**绝对价位水平**」，被 `ffill` 往后带；
`STAGE` 问的是「**今天的**收盘价落在这些**当时的**价位水平的哪里」。用当前价缩放
等于让带跟着今天的价走 ⇒ 今天的价永远落在同一相对位置。

⇒ **因此必须一并落「锚日期」**（新列 `FLD.GARIDENT_PRICE_ANCHOR`，与 `GAR_P` **同步
ffill**）：读侧 `GAR_P = 比值 × qfq_close(锚日期)`，价格只从 K 线取（**单一真相源**）。

### 边界

上面「不变」的前提是**新事件在锚之后**（正常情况）。若**源端回补更早的事件**
（事件日期 < 锚），整窗只有一部分被缩放 ⇒ **非均匀** ⇒ 比值不再不变。那正是
`--save-margin-days` 的场景，处置是**重算那批窗口**，不装作没发生。

### 这条要泛化

> **凡是由价格序列导出的「绝对价位」，一律存成相对锚 bar close 的比值；绝对价格只存在 K 线里。**

同病者**尚未处理**：`STOCK_TREND_CHECKOUT_CLOSE`（已删，见下）、`BOTTOM_PRICE` /
`ROOF_PRICE`（`ChipDistribution_jit.py:1123-1125` 同时取这两个，从名字看就是绝对价位）。

## 六、Poly9 核：`rolling_poly9_v2`（**刻意不做 JIT**）

搬进 `analysis/timeseries.py`（老树同位置）。`POLYNOMIAL9` 的生产核：
滑动窗 Chebyshev 九次拟合、每窗只取**端点值** ⇒ 一条去噪趋势线。
`POLYNOMIAL9_DELTA` / `POLYNOMIAL9_TIMING_LAG` 建在它上面。

**递归折半**是 `_v2` 与 `_v1` 的唯一区别：`w` 大而序列短时直接开窗会得到一整段 NaN，
故把 `w` 折半**递归**、前缀 `s[:w-1]` 也用 `w/2` 递归补。实测 `w=252`、`len=900`
的实际路径是 `252 → 126 → 63`，三段拼起来恰好 900。

### ⚠️ 为什么**不** JIT（与用户的「能 JIT 最好」有冲突，已当面说明）

它的热循环是 `map(last_poly9, windows)`，而每次迭代调的是
`np.polynomial.Chebyshev.fit` —— **numpy 的 C 实现**，numba 编译不了。
硬写成手搓最小二乘会**动最低位**，直接破坏 `array_equal` 对拍。
这一族真正该 JIT 的是 `mapower_np_vXIIs` / `inv_nums`（O(n²) 双重 Python 循环，
**老树本来就 `@nb.jit`**）与 `magic_nine`（逐 bar 循环）。

## 九、Poly9 家族其余：`mapower` + `TA_HMA`（**范围比方案更小**）

### `mapower_np_vXIIs` / `inv_nums` → `analysis/quadrant.py`（+ `quadrant_jit.py`）

**MA 均线多头排列能量强度**（`POLYNOMIAL9_NORM` 的生产核）：对每个 bar 数各条均线
（默认 5..29 共 25 条）的**逆序数**，归一化成 `[0,1]`。

⚠️ **别高估它的成本**：`inv_nums` 收到的是「25 条均线」那条切片，
所以是 **25² 量级**，不是价格序列长度的平方。实测 5000 根纯 Python 也在秒级 ——
JIT 是**锦上添花**，与 `renko_jit`（实测 **654×**）不是一个量级，**别照抄那个结论**。

⚠️ **两个可证性质写进了 doctest**：前 `max(range_list)-1` 个是 **0 不是 NaN**（下游别
当"无数据"去 drop）；`range_list` 里**不能有 1**（`np.convolve(...)[0:0]` 是空数组，
形状不匹配直接抛 —— 老树也一样）。

⚠️ 老树有多个**孪生**：`inv_num`（int32/f8 版）、`mapower_np_vXII`（f8 版）——
按「多副本只搬规范版」**只搬 `_vXIIs`**（`reviews.py:1606` 主路径在用的那份）。

### `TA_HMA` → `analysis/indicators.py`

`POLYNOMIAL9` 的输入是 `s = [close[:11], HMA10[11:]]`，所以 HMA 是必需的。

原本取自 **QUANTAXIS**（`QAIndicator/talib_numpy.py:178`），而它已按 D12 全树剔除。

没有消费方就不搬。用户那句「如果不相同也用 `talib.MACD` 代替」**仍然有效**，
留给搬 M9T `_baseline` 那一轮执行。

### ⚠️ `sklearn` / `kneed` **不在 `MIN_PACKAGES`** —— 故改成惰性 import

`analysis/stages.py` 原本**模块级** import 这两个，而它们**都没进

**若将这条链接进 `--save`，应把两者提升进 `MIN_PACKAGES`** —— 那时缺了就是硬断，
该由自检拦，而不是等到调用点才炸。

## 十、Poly9 编排：`analysis/poly9.py`（**算法侧到此收口**）

`calc_polynomial9_vXIs`（老树 `features/base.py:2091`，逐字搬）+ `calc_polynomial9_norm_vXIs`。

### 拼 `s` 的那两个数字是绑死的

```
s = np.r_[close[0:11], HMA10[11:]]
```

`TA_HMA(period=10)` 的暖机长度**正好 11**（前 11 个是 `NaN`），所以前 11 根必须用原始
收盘价顶掉。**那 11 与 `period=10` 绑死** —— 换 HMA 周期就得改拼接位置，否则给
`rolling_poly9_v2` 喂进 `NaN`，而它是 Chebyshev 拟合，`NaN` 会一路扩散。
提到模块级常量 `HMA_WARMUP` 并有专测。

### 两处刻意的结构决定

* **`POLYNOMIAL9_NORM` 提成具名函数**：老树把那一行**内联在调用方**
  （`reviews.py:1606`，带 `annual > 200` 的闸）。闸是**策略**，散在调用方会被各处抄一遍
  —— 提出来才能钉住、才能被对拍覆盖。**算术一字未改**（`range_list` 仍是 5..29）。
* **`*_REAL` 那一族不在这里**：它们是周/月线重采样后的 **rename**，
  属更外层（老树在 `empirical.py:3838` 的 rename map）。等解 `features/` 那两个 stub 时再落。

### ⚠️ 唯一一处偏离逐字照搬

老树 `features is None` 时**无条件 `print`** 后返回。本树把打印收进 `verbose` ——
子层裸 `print` 会打花 banner（`PITFALLS.md` **P22**）。**返回 `None` 的语义保留**
（调用方按返回值判空），信息一个字没少，只是默认不吵。

### 这份对拍同时是 `TA_HMA` 的真验证

`TA_HMA` 没法单独与老树对拍 —— 老树那份来自 **QUANTAXIS 包**，一 import 就踩
`test_no_quantaxis` 的「运行时不许加载 QUANTAXIS」。而 `HMA10` 在这条链上是
**被真正消费**的 ⇒ **端到端逐值相同**就说明它与 QUANTAXIS 那份在这个用法上等价。

### ⚠️ 对拍 harness 又踩了两个坑（都是"逐字搬"之外的坑）

1. **老 `features/base.py` 有**两处** `from GolemQ.analysis.timeseries import …`**
   （`:70` 与 `:2927`），十几个名字，第二处还夹着新树没有的
   （`resample_multi_frequency_indices_func`）⇒ 逐个枚举必漏。
   正解：给**真模块**挂一个兜底的**模块级 `__getattr__`**（PEP 562）——
   `from X import Y` 走的就是 `getattr(X, 'Y')`。
2. **老模块的 `FLD` 必须是"新树优先、老表兜底"的代理**：只用新表 → 老模块**模块体**
   里就 `AttributeError`；只用老表 → 老函数写出老列名（`poly9_delta`）而用例读新列名
   （`poly9Delta`）⇒ `KeyError`。**两个方向都实测踩过。**
   已抽成 `old_tree.field_compat()`，并把 `test_stages` 里那份硬编码版本也换掉。

⚠️ 该代理**不掩盖真实差异**：两边都有的列一律取新树的值 ⇒ 对拍仍是在比**值**。
