# D19. CLI 退出码口径：**用法/参数错 = 2，运行期失败 = 1**

- **编号**：D19
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D19 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：全 CLI 按这一条分：**「调用错了」→ 2**、**「跑起来没成」→ 1**。
与 argparse 的约定一致（`usage:` 输出本来就是 2 的语义）。

| 路径 | 码 | |
|:--|--:|:--|
| 未知开关 / `--save tdxx` / `--save ''` | 2 | argparse 自己报 |
| `--purge-l1 tdx`（取值非法）| 2 | `usage_error` |
| `--save-collections stock_lsit`（集合名打错）| 2 | `usage_error` |
| `--eneloop-add` 缺 `--symbols` | 2 | `usage_error` |
| `--sub <键不存在>` | 2 | `usage_error` |
| `--save qmt` 所有参考集合都取不到 | 1 | 运行期 |
| `--migrate-*` 搬过来 0 行 | 1 | 运行期 |
| `--sub` 的订阅器**跑起来**抛异常 | 1 | 运行期 |
| Ctrl-C | 0 | 刻意（用户主动停）|

**为什么要有 `usage_error`**：有一类取值合法性 argparse **表达不了** —— 合法集来自
**运行期注册表**（`--sub` 的订阅器键、`--save-collections` 的集合名）。那几处只能自己报，
但必须报成**同一个形状、同一个退出码**。实测过混用：`--save tdxx` 给 2 而
`--purge-l1 tdx` 给 1 —— **同一类错误在 CLI 上有两种表现**（用户指出）。

`usage_error` 打的是与 `argparse.ArgumentParser.error` **同构**的
``usage: …`` + ``<prog>: error: <msg>``（都进 stderr），另可带一行中文提示。

⚠️ **版权行要 `flush=True`**：stdout 被重定向时是块缓冲，而 argparse 的 usage 走
stderr（无缓冲）—— 不 flush 的话版权行会**排到 error 行后面**。实测踩过。

**连带**：`--save` 的取值校验改用 argparse `choices=`（见 D18），所以
`run_save` 里那段手写校验删掉了 —— 一处真相源。
