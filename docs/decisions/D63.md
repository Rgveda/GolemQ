## 一、千股千评：复用现有取数

`markets/StockCN/crawler/moneyflow.py::save_moneyflow(source='eastmoney')` 已经存在
（`--moneyflow eastmoney` 的同一实现）：东财 `ak.stock_comment_em`，约 5200 行 /
11 次分页 / ~3s，落 `stock_reality_feat_day` 的 9 列。

`--save tdx` 直接调它，**不新增第二份取数**。它写的 `TurnoverRate`（÷100）与
`refresh_turnover` 的 8.3 现算**是同源同值**（`crawler/moneyflow.py` 模块 docstring
2026-10-11 实测），所以先后写同一列不是口径冲突，而是刷新。

## 二、牛股诊股：页面已改版，重写解析

旧树 `fetch/crawler.py::get_stock_diagnosis_details` 抓的是
`stockpage.10jqka.com.cn/<code>/` 的 `analyze-tips` / `analyze-txt` /
`analyze-stars`。**2026-10-22 实测那些 class 一个都没有了**：

* `stockpage` 现在的标题是「个股资金流向查询」；
* 诊股页搬到了 **`doctor.10jqka.com.cn/<code>/`**（「牛叉诊股」），结构换成
  「综合诊断 + 五个维度」。

新增 `markets/StockCN/crawler/diagnosis.py`：

| 页面 | 落库列 |
|:--|:--|
| 综合诊断 6.7 分 | `overall` |
| 打败了 98% 的股票 | `pctRank`（小数 0.98） |
| 技术面 / 资金面 / 消息面 / 行业面 / 基本面 | `TechScr` / `MoneyflowScr` / `NewsScr` / `IndustryScr` / `BasicScr` |
| 平均成本 1314.02 元 | `DiagAvgCost` |

* **必须按段落 id 定位**（`nav_technical` / `nav_funds` / `nav_message` /
  `nav_trade` / `nav_basic`）。只按「…面诊股」文字找 `诊断结果` 时，页顶导航
  会让五段全部命中**技术面**那一个 —— 实测五维全等于 7.5，是静默错值。
* **日期取页面「诊断日期」**，不取 `today()`。周末抓到的应是上一交易日；
  用 `today()` 会写出当天并不存在的行。
* 落 `stock_reality_feat_day`（D50），走 `save_reality_feat` 共用写口；
  只写 `DIAG_PAYLOAD` 白名单里的列，不碰同文档里别人的列。

## 三、执行方式与代价

* `--save tdx` / `--save pytdx` 的非干跑才做（与 turnover/moneyflow 同一个闸）。
* 四件事**逐件降级**：任一源失败只把 banner 节点留灰 + 打一行
  `[reality_feat_day] …本次未落库`，不拖垮整条 `--save`。
* 牛股诊股**逐只 HTTP**（~0.2s/只 + `DIAG_DELAY=0.2` 间隔），全市场 5000+
  只约 **20–40 分钟**，排在元数据段最后。`--save-codes` 给了就只抓那几只。
* 页面 `charset=GBK`，`requests` 猜编码会乱码 —— 显式 `resp.encoding='gbk'`。

## 四、短路判断（2026-10-22 补）

同一交易日的快照重复跑没有新信息，且牛股诊股全市场要 20–40 分钟。两个源都加当日覆盖闸：

* `metadata_save.metadata_covered(field, day, codes=None)` —— 按 `date_stamp`
  取某日某列已写入的 code 集合（只读）；
* 覆盖 >= `COVERAGE_SKIP_RATIO`（**90%**）⇒ 跳过抓取；部分覆盖（上次半途失败）
  不达阈值仍重抓补齐；`dry_run` 不短路；
* 标记列：千股千评 `TotalScore`，牛股诊股 `TechScr`；
* ⚠️ 阈值不能取 95%：千股千评实测 ~5200 行 / `stock_list` 5580 只
  （北交所/停牌/无评分没有），95% 会让完整抓取也被判成没跑完。
