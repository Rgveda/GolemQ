# D78. 60min 一体化特征行 + 全量 as-of（撤销 D74）

- **编号**：D78
- **日期**：2026-10-30
- **权威规格**：[`docs/review_model_60min_feature_spec.md`](../review_model_60min_feature_spec.md) —— **列清单、口径、回填策略以它为准**
- **审计**：[`docs/review_model_asof_audit.md`](../review_model_asof_audit.md)

## 背景

1. D74 把 `se` / `ZenPivotCnt` 挪到日族，用户判定「没考虑成熟」——两列应在
   **60min 上跑并落 `*_reality_feat_60min`**；
2. `--review` 的 60min 行应是**一体化特征行**：zen / minor / se /
   ZenPivotCnt / Renko / M9T / Poly9 / RegTree / Prophet / STAGE 全部在
   60min 口径下产出，Renko 不拆日线；
3. review 必须**逐日 as-of**：CZSC / Renko 会随后续 bar 改写早期结论，
   「整条序列跑完再按时间过滤」是后视镜。

## 决定

1. **`HOUR_COLUMNS` = 74 列**（明细见 spec）：
   60min 原生 48（zen 4 + minor 17 + se/中枢 2 + Renko 14 + 原生组 11）
   + coldstart 12（日频采样）+ 日族 14（采样）。
2. **日频特征（`Maj`/`Wek`）两表都留**：日表原生计算 + 采样进 60min，两表同值。
3. **每类指标另有 60min 原生版**（同算法、60min K 线、2160 根 as-of）：
   `stage`、`m9t`/`m9tLag`、`poly9D`/`poly9NorR`、`rTrePrcD`/`rTreLagR`/
   `rTreSlopD`、`prophetLbD`/`prophetUbD`/`prophetClrNorm`、Renko 14、se/中枢。
4. **as-of 口径**：每个交易日 15:00 用 ≤T 的最近 2160 根重算；盘中 3 根
   日频列沿用上一交易日；60min 取数从 2016 锚点（头部 ≥2160 根暖机）。
   实测证据：CZSC 44/47/12、Renko 7/8 与 -18/-50。
5. **Garident Price**：`garPD` 稀疏，按用户要求 **ffill**，`garPAnchor`
   等伴随列同步前填（还原时锚一致）。
6. **回填**：历史全补（一次性，`backfill_hour_extra --apply --redo`），
   之后每日增量；日表 Renko 14 列与 `se`/`ZenPivotCnt` 用 `$unset` 清掉。

* `test_reality_attach::test_hour_extra_is_attached_from_60min`（含 Renko）；
* 全量 `run_tests.py`（1008 条）。
