# D22. 通达信服务器池：**每周探活一次**，活动列表落 `~/.GolemQ`，**不硬编码**

- **编号**：D22
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D22 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：新增 `markets/StockCN/datasource/tdx_hosts.py` +
CLI `--update-tdx-hosts [--force]`。机制：

1. **候选**：pytdx 包内自带的 `pytdx.util.best_ip.stock_ip`（**64 台**，上游维护）
   ∪ 手写兜底。**不自己爬网页** —— 包里那张表就是别人维护好的，再造爬虫是第二个轮子，
   还得跟着网页改版维护。
2. **探活**：**真协议调用**，每台测 `ATTEMPTS=3` 次，按**成功次数的中位延迟**排序，
   失败率 > `MAX_FAIL_RATE` 剔除。全池 66 台并行探约 1 分钟。
3. **缓存**：`~/.GolemQ/settings/tdx_hosts.json`（含 `probed_at` / `median_ms` /
   `runs` / `fail_rate`）。**用文件不用 Mongo** —— 本模块在 `datasource/`，
   而 `CLAUDE.md` 明令 DB 操作只能进 `services/`。
4. **每周一次**：**缓存文件的 mtime 就是起算点** —— 不再引一套签到表，
   也就不必让这个命令依赖 DB（`needs_db=False`）。
5. **`TdxSource.hosts` 的优先级**：显式传入 > 缓存 > pytdx 包内池 > 手写兜底。
   **正常路径不经过任何硬编码 IP。**

实测（2026-10-09）：探到 **66 台可用**，最快的 75.8ms（`124.71.9.153`），
全部写进 `~/.GolemQ/settings/tdx_hosts.json`；`TdxSource()` 随即拿到 66 台。

### 四条踩出来的纪律（每条都有一条测试钉着）

1. **单次探测分辨不出「间歇」。** 同一台 `123.125.108.14`：一次连测 5 次全部
   超时 10s，几十分钟后再测 **6/6 成功、中位 0.233s**。**它不是死的，是看负载的。**
   所以必须**多测取中位**，不能一锤定音。
2. **探针必须跑「生产实际用的那个调用」。** 本项目 `new_api()` 用
   `get_security_count(0)`，而 pytdx 的 `best_ip.ping()` 用 `get_security_list(0,0)` ——
   **两者不等价**：实测那台间歇服在 `get_security_count` 上超时、在
   `get_security_list` 上正常。所以**不能拿 `select_best_ip()` 顶替**，
   它会把坏服判成好的。
3. **必须判返回值，不能只判「没抛异常」。** pytdx 连不上时**不抛异常**：
   `connect()` 内部重试约 7s 后返回，`get_security_count()` 返回 **`None`**
   （`PITFALLS.md` P3b 的同一形态）。只判异常会把死服判成 **7.03s「成功」**
   混进结果 —— **这条是单测抓出来的，不是我读代码看出来的**。
4. **回环地址按「地址本身」拒绝，不靠"反正连不上"。** 本机若真有东西监听 7709，
   探针会收进来，而**由此产生的行情数据是假的**。`is_loopback()` 覆盖
   `127.0.0.0/8` / `::1` / `0.0.0.0`。

⚠️ 另外：探测**全灭时保留旧缓存**，不把可用列表清空 —— 网络抖动时清空是自毁。
