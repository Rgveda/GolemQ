- **编号**：D66
- **日期**：2026-10-25

**背景**：老树 `GolemQ_old/analysis/base.py:461-671` 的 `calc_four_quadrant_boost`
尾部有一段 `codex_01..codex_15` → `QuadSt`（位掩码）→ `ChoBits`（十六进制串）
→ `QuadCodex`（前三次状态拼接）的状态机。新树按「逐字搬」一并搬进了

用户 2026-10-25 指出：`--review` 里这三列**没有消费方**，不必计算。

## 一、核查结论

**新树零消费方**

* `pipeline/review/contract.py` 的三族列（day / 60min / 15min）里**没有**这三列，
  落库时按契约过滤 ⇒ 从来没写进任何 `*_reality_feat_*` 表；
* 全树 `grep`（`.py` / `.md` / `.ipynb`）只有定义处引用这三个常量；
* `models/alias.py` 里保留的 `QUADRANT_STATUS` / `CHOBITS` / `QUADRANT_CODEX`
  是真值字段名（老树数据契约），**不删**，只是不再被计算；
* 老树唯一的消费方是 `models/fourquad.py`（`Chobyte` / `QChoEngMaj`），该模块
  **未搬**，也没有搬迁计划。

**成本**（实测，2,160 根 15min 窗口，与 `--review` 的 `WINDOW15` 一致）：

| 项 | 耗时 |
|:--|--:|
| `calc_four_quadrant_boost` 全函数 | 41.0 ms / 次 |
| 状态机那一段 | 13.2 ms / 次（**32.1%**） |

`zen_snapshots` 对每个 60min 目标调一次 `minor_features` → 每码约 2,160 次
⇒ **约 28 秒/码** 的纯浪费（全量回填单码约 36–40 分钟，约 1.2%）。

* `analysis/quadrant_jit.py`：删掉 `fourQuad_autocodex_candidate` 起、到
  `features[LTT.QUADRANT_CODEX] = ...` 止的 **212 行**；
* 模块 docstring 的「解耦动作」增第 4 条，写明删了什么、为什么、对拍口径；
* `test_cases/analysis/test_quadrant.py`：老树对拍改用
  `_assert_same_columns(..., ignore=_DROPPED)`，显式排除这三列，其余列仍逐值
  `array_equal`（D36 不放松）。

**为什么删而不是加开关**：没有任何消费方，加 `with_codex=False` 只会把死代码
留在库里、并在下一个调用点再问一次。若将来真搬 `models/fourquad.py`，按 D35
「只搬一条」的规矩**从老树重新搬**，不靠新树的残件。
