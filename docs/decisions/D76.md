# D76. `BOTTOM_PRICE` / `ROOF_PRICE` 是**绝对价**，不归一化、不落库

- **编号**：D76
- **日期**：2026-10-28
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D76`，或直接开这个文件

**背景**：D49 §三把 `BOTTOM_PRICE` / `ROOF_PRICE` 记成「比值原则的同病列、尚未处理」。
用户 2026-10-28 更正：

> `BOTTOM_PRICE` / `ROOF_PRICE` **就是绝对价**。链路是：
> 读取 `GARDIENT_PRICE_DUMMY` 相对价格 → 恢复 `GARDIENT_PRICE` 绝对价格
> → 提取 `BOTTOM_PRICE` / `ROOF_PRICE` 绝对价格。这条链路很清晰。

## 一、口径

```
garPD（落库比值）
  └─ × garPAnchor 当天的 close        （reality_attach._restore_garident_bands）
       └─ garP（绝对价带，list[(上沿, 下沿), ...]）
            ├─ ROOF_PRICE   = bands[-1][0]   （最近一段的顶）
            └─ BOTTOM_PRICE = bands[0][1]    （最早一段的底）
```

* `btmP` / `roofP` 是**绝对价**，**不进 `PRICE_RATIO_COLUMNS`**；
* **不落库**：它们只在上层读取/attach 时从**已还原的** `garP` 现取；
* 复权口径跟随 `garP` 的还原（乘锚 bar 的 close，D49/D70）。

## 二、代码改动

* `core/constants.py` 补老树真值（PITFALLS P1）：
  - `FIELD.BOTTOM_PRICE = 'btmP'`
  - `FIELD.ROOF_PRICE   = 'roofP'`
  （此前**未定义**，`ChipDistribution_jit.py:1126-1127` 一旦走到那支就会
  `AttributeError`；现补上。）
* `analysis/stages.py` 新增纯函数 `garident_bottom_roof(bands)`（带 doctest）：
  `(bands[0][1], bands[-1][0])`，缺失返回 `(nan, nan)`；与老树
  `zen_pivot._garident_roof_or_bottom` 同口径。
* `analysis/reality_attach.py`：`_restore_garident_bands` 还原 `garP` 后，
  立即产出 `btmP` / `roofP` 两列；`loaded['garident']` 记录三列。
  **不写库**。
* `ChipDistribution_jit.py` 的消费分支保持原样（此前常量不存在是它潜在的死雷）。

## 三、边界

* 这两列**不在 review 契约、不进 DB** —— 不要「顺手」加进 `DAY_COLUMNS` /
  回填工具；否则又会变成冻结复权锚的绝对价存量。
* `garP` 本身仍按 D70 存 `garPD` 比值；绝对价只在读取层出现。

  `btmP=1.0`、`roofP=1.1`，且 `loaded['garident']` 含三列；
