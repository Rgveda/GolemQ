### 一、`scopes.py` → `analysis/cv/scopes.py`（跨市场）

**决定**：只搬**「怎么切」**，注入**「拿什么切」**。

* 根层留下：六个 scope 的名字与含义、`etc = 全市场 − focus_block`、`etc_1/etc_2` 的
  奇偶二分与 `>1700` 阈值、空清单护栏（返 `False` + 打印原因）、未知名报错。
* 经 `dataset` 参数注入（`:class:`ScanDataset``，四项）：名单 / 板块成分 / 板块名清单 /
  `etf` 码表。A 股侧由 `StockCN.scan_dataset()` **薄封现有读口**提供 ——
  `refdata.GQ_fetch_stock_list` / `GQ_fetch_stock_block` / `symbol.focus_block` /
  `symbol.ETF_LEGACY_CODES`（那张 506 码表也随之下迁到 `symbol.py`，与 `focus_block` 并列）。

**为什么不新建注册机制**：`GQMARKETS` 已经是注册表、StockCN 导入即自注册
（用户：「不需要子注册，StockCN 已经自注册了」）。再叠一层 scopes 注册表是同一件事做两遍。

**搬的动因**：原先它 `from .refdata import …` —— 一个**根层模块直连市场包**，
与「取数的唯一入口是市场实例」和「库名不外泄」两条硬规定都冲突。
全树当时唯一的同类坏先例是 `analysis/ChipDistribution_jit.py:55`。

返回 `600xxx.SH` 假码，名字却像「取全部码」。真名单只有 `refdata.GQ_fetch_stock_list`。

**对拍**：六个 scope 与旧实现**逐值相同**（`fast`/`block` 1671、`etf` 506、
`etc` 3909、`etc_1` 1908、`etc_2` 2001）。

### 二、筹码分布不再自补换手率（`ChipDistribution_jit.py`）

**删**：`get_data` 里 `vol / liutongguben` 现算 + 尾部逐日填补那一整段。
**留**：读 baostock `turnover` 列、读东财 `TurnoverRate` 列补缺口 —— 那是**读库**、
两列口径与覆盖期不同、取并集是正确读法，不是「修补」。
**增**：两源读完后仍缺 ⇒ **抛 `ValueError`**，消息点名 `fill_turnover`。

理由三条（都不是洁癖）：

1. 老修补**失败是静默的**（最末一支只 `print` 一行就继续），而换手率是**所有**下游结论的
   系数（`_calcu_sin_jit` 的 `TurnoverRateT * A`）——错一天就错一片。
2. 「恰好缺今天这一天」是**日常**情形（`--save` 先写 K 线、后写元数据；盘中跑筹码分布
   必然缺当日换手率）⇒ 那三条分支里的主路径不是异常路径。做成静默兜底等于让
   「数据还没到」永远不被发现。
3. 那段里 `total_volume` 在 `else` 分支后仍被引用（老 `:784` / `:818`），是一条
   **没跑到的 `UnboundLocalError`**。删掉连它一起带走。

**删得安全**：进 `get_data` 的唯一路径 `calc_stock_chip_distribution_jit` **全树无人调用**
（`features/` `pipeline/` 零引用，单元用例也绕开 `get_data`）——今天没有任何东西依赖它。

### 三、补齐函数落 `markets/StockCN/metadata_save.fill_turnover`

与 `save_turnover` / `refresh_turnover` 同址（都写 `stock_metadata_day`）。
只补**真的缺**的日子（两列任一有值即算覆盖），写 **`turnover`** 那列 ——
口径同源（按**流通**股本），且筹码分布的**第一读**取的就是它。

**⚠️ 补算公式：老树多除了一个 100，是错的 —— 这里不照搬**

老树四处（`ChipDistribution_jit.py:785/:819/:865`、`realtime.py`）都写
`(vol * 100 / liutongguben) / 100`。实测 600519 的 `vol` 以**手**计
（`amount / volume` 恒是股价的 100 倍）、`liutongguben` 以**股**计 ⇒ 正确式子是
`vol * 100 / liutongguben`。用真实数据对拍 baostock 的 `turnover`：

| 日 | volume | 本函数 | baostock `turnover` |
|:--|--:|--:|--:|
| 2026-09-28 | 28218 | 0.002257 | 0.0022572926 |
| 2026-09-29 | 26366 | 0.002109 | 0.0021091423 |
| 2026-09-30 | 38330 | 0.003066 | 0.0030662799 |

老式子给的是 `2.3e-05`（**恒小 100 倍**）。没被发现是因为那段逻辑从没被调用过。
**照搬等于把一条已知错误落进库里**，故取修正后的式子，阈值仍照老树（`0.96`）。

`realtime.py` 的那处内联**收敛**到本函数（同一公式不再有第二份），
⇒ 实时日线 bar 的 `TurnoverRate` 取值随之**修正**（原先小 100 倍；该值只进内存帧、不落库）。

### 四、顺带修掉的两处静默缺陷（都由新用例逮到）

1. **两源都空时那一列根本不存在** ⇒ 几处 `dropna(subset=['TurnoverRate'])` 抛
   `KeyError: TurnoverRate`，而不是「缺数据」。现在先补 NaN 列，让「缺」走到明确的抛出点。
2. **空结果是没有列的**（`refdata._read` 空集返**空帧**不是 `None`）⇒ 第二个源那段
   `dropna` / `.loc[:, [col]]` 同样抛 KeyError。现在先判列。

### 五、CLI：`--fill-turnover`

用户定了要有手工入口，落在 `cli/commands/fill_turnover.py`（照 `moneyflow.py` 的形状：
只做参数校验 + 委托）。**注册位置在线性表里是 `MONEYFLOW` 之后、`METADATA_ALIGN` 之前** ——
`--metadata-align` 是**只读报告**，必须跑在写路径后面才看得出刚补上的列。

```
--fill-turnover                        # 默认全市场、最近 7 个自然日（与 --save-turnover-days 同口径）
--fill-turnover-codes 600519,000001    # 缩范围
--fill-turnover-start/--fill-turnover-end
```

为此 `fill_turnover(codes=...)` 的契约放宽成：**`None` ⇒ 全市场**
（`refdata.GQ_fetch_stock_list`）。「全市场是哪些」属于市场层，不该由 CLI 自己拼。
显式给**空列表**仍报错 —— 那是调用方的 bug，不是「全市场」的意思。

**没接进 `--save`**（那会改日更语义）。
