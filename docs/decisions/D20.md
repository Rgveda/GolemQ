# D20. CLI 环境自检（`cli/bootstrap.py`）：版权页 + 环境 / 配置 / 服务三道闸

- **编号**：D20
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D20 DECISIONS.md`，或直接开这个文件

**决定**（2026-10-09）：环境自检独立成 `cli/bootstrap.py` —— `__main__.py` 只管
「建 parser → 分发 → help」（D17）。检这些：

| 项 | 判据 | 不满足时 |
|:--|:--|:--|
| 版权页 | `bootstrap.copyright_infos` | **每次运行都打** |
| TTY | 复用 `core.presentation.ansi_enabled()` | **只作信息**（`-v` 下 `ℹ`），**不算不通过** |
| python | `>= 3.12` | 警告 |
| numpy / pandas / polars | `>= 2.0` / **`2.3`** / `1.24` | 警告 |

**pandas 为什么是 2.3**（2026-10-09 订正）：3.0 之前的**最后一个 2.x 是 2.3.3**
（2025-09-29 发布；3.0.0 是 2026-01-21），且 pandas 官方升级路径就是「先升到 2.3、
把告警清干净，再上 3.0」。门槛定在 2.3 既是最高的 2.x，也**顺带接纳 3.x**
（版本元组比较 `3.x > 2.3`，不必再写一条）。
⚠️ 最初按口头说法写成了 `2.5` —— **那个版本不存在**，于是这条检查**永远不可能通过**，
而且从输出上看不出错（只是一个恒红的 ⚠️）。**门槛值必须是真实存在的版本。**
| 配置文件 | `~/.GolemQ/settings/config.ini` 在、可解析、有 `[MONGODB] uri` | 警告 |
| MongoDB | 连得上**且版本 `>= 8.3`** | **硬失败**（`EXIT_FAILURE`）|

**时机分三段，这是刻意的**：

* **版权页**在 `parse_args()` **之前**打 → `--help` 与 argparse 的用法错误上也看得见
  （「全局输出」的意思）。
* **本地自检**在解析**之后** —— 详略要由 `--verbose` 定。
* **Mongo 自检**在**知道是哪条命令之后**，且只对 `Command.needs_db` 的命令。

**三条刻意的口径（每条都有代价，别"顺手统一"）**：

1. **版本不满足只警告，不拦。** 实测本机 `pandas 2.2.3 < 2.3`：硬失败会让 CLI
   **立刻全废**，而版本问题 CLI 自己也修不了。
2. **TTY 不算「不通过」。** 管道/重定向是**正常用法** —— 把它混进 pass/fail，
   每次 `... > out.txt` 都会白打一个 ⚠️。
3. **配置类命令 `needs_db=False`**：`--setup` / `--mongodb-init` / `--dingtalk-init` /
   `--serverchan-init` / `--sub` —— 它们的作用就是**修配置**，要求先连上库等于
   「配置连错了就永远修不回来」。`needs_db` **默认 True**：忘了声明只会多连一次，
   不会静默漏检。

**连库超时 3 秒**（`MONGO_TIMEOUT_MS`）：pymongo 默认 `serverSelectionTimeoutMS` 是
30s，服务器不可达时是**一次挂死** —— 而自检的意义就是别让人干等。为此给
`core.mongo.GQ_util_mongodb_client` 加了直通 `**kwargs`（**不是**在 bootstrap 里
再建一个 client —— 那样就有第三个建 client 的地方了）。

⚠️ **顺手修了一处文档错误**：`CLAUDE.md` 有三处把配置写成
`~/.GolemQ/config.ini`，**真身是 `~/.GolemQ/settings/config.ini`**
（`core.path.setting_path`；`core/settings.py` 的 `CONFIGFILE_PATH` 也是这么拼的）。
只有 `setup_mongodb_config` 里一处老逻辑还提过前者。已改准。
