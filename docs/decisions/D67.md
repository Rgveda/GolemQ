# D67. 删除 review 的 M9T lag 列（`m9tLag` / `m9tLagD` 都不再落库）

- **编号**：D67
- **日期**：2026-10-27
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D67`，或直接开这个文件

**背景**：新树有两套 M9T lag，曾经同名：

* compact 60min 的 `FIELD.MAGIC_NINE_TURNS_TIMING_LAG = 'm9tLag'`（`analysis/compact.py`）；
* review `COLDSTART_COLUMNS` 里也写 `'m9tLag'`（日尺度，老 `M9T_LAG`）。

核查结果：

1. review 这列**没有生产者**（`hour_legacy` step 不存在；`_coldstart_row` 只返回
   `m9t`/`m9tMaj`）；
2. 库里 `stock_reality_feat_60min` 的 **3,720,260** 行 `m9tLag` **全是 `None`**；
   `m9tLagD` / `m9tLagR` 均 0 行；
3. attach 又因为「compact 已算的列不覆盖」，review 的 `m9tLag` 根本不会附加。

用户 2026-10-27 的口径：**如果库里全为 NaN 或没有，就把 `--review` 的落库和
attach 读取都删掉**。

## 一、删除

* `pipeline/review/contract.py`：`COLDSTART_COLUMNS` 移除 M9T lag 列；
  `LEGACY_RENAME` 删除 `M9T_LAG` 映射；
* `pipeline/review/coldstart.py::_coldstart_row` 不再返回该列；
* `analysis/reality_attach.py` 通过 `COLDSTART_COLUMNS` 自动不再附加；
* 不新增 `m9tLagD` 的 review 生产者，也不做存量迁移（旧值全是 None）。

## 二、保留的定义

* compact 的 `FIELD.MAGIC_NINE_TURNS_TIMING_LAG = 'm9tLag'` **不动**；
* 老树 `FEATURES.MAGIC_NINE_TURNS_TIMING_LAG_REAL = 'm9tLagR'` **保留常量定义**
  （老树真值，留给模型/后续），但当前 review **不生产、不落库、不 attach**；
* 不保留 `MAGIC_NINE_TURNS_TIMING_LAG_DUMMY`（原先临时提议的 `m9tLagD`）。

## 三、顺带修正：盘中 coldstart 的上一交易日缓存

`day_core_step` 原来只对 `day_targets`（delta 跑一天时只有当天）算 coldstart 行，
而 `coldstart_step` 的盘中 bar 要用 `< 当日` 的缓存 ⇒ 所有 coldstart 列（`stage` /
`bstStgBf` / `m9t` / `prophet*`）盘中 NaN。现在 `day_core_step` 把
**上一可用交易日**也纳入 `need_dates`（只算 cold 行，不算 day 行），
盘中能取到上一交易日值，15:00 仍用当日。

## 四、验证

* `COLDSTART_COLUMNS` 不含 `m9tLag` / `m9tLagD` / `m9tLagR`；
* 60min review 输出不再有 `m9tLagD`；`stage` / `m9t` / `prophetLbMaj` 在
  2026-10-26 四个 bar 都有值（盘中=上一交易日，15:00=当日）；
* `test_reality_attach::test_review_m9t_lag_columns_are_not_in_contract` 钉住删除；
* 全量测试全绿。
