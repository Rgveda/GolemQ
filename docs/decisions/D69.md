# D69. review 新增契约列不会自动回填旧行；用 `tools/backfill_hour_extra.py` 补

- **编号**：D69
- **日期**：2026-10-27
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D69`，或直接开这个文件

> ⚠️ **已被 D74 取代**：`se` / `ZenPivotCnt` 2026-10-28 起移到**日族**，
> `tools/backfill_hour_extra.py` 已删除；日族补齐改用
> `tools/backfill_day_extra.py`。本文记录的是当时 60min 口径的历史。

**背景**：`ZenPivotCnt` / `se` 是 **2026-10-20 18:26（commit `7530a5a`）** 才加进
review 契约的。review 的持久化判据是
`pipeline/review/persistence.py::persisted_keys`：

> 一行里**任一契约列非空** ⇒ 视为已持久化（`min_columns=1`）。

所以：

* 在 2026-10-20 之前已经写过的行，**不会**因为后来新增的 `ZenPivotCnt`/`se`
  被重新计算；
* 只有之后新写/缺失的 bar 才带这两列。

## 一、实际覆盖（2026-10-27 实测）

`stock_reality_feat_60min`：

```
ZenPivotCnt 非空 3,750,712 行；覆盖 1,835 个码
其中 1,810 个码 >=100 行（多为 2,128 行，覆盖 800 天目标窗口）
只有 27 个码 <100 行（合计约 47,321 行待补）
```

`000711` 是 27 个之一：2,075 行 review 数据，但只有 **15 行**有
`ZenPivotCnt`/`se`（2026-10-20 ~ 10-23）；它的历史行写于 2026-10-19（早于
commit `7530a5a`）。`300085` / `002491` / `600519` 等 1,810 个码是之后写的，
2,000+ 行全带这两列。

**结论：一个多星期的 review 没有白跑** —— 绝大多数码是完整的；只有早期批次
27 个码缺这两列。

## 二、补法

新增 `tools/backfill_hour_extra.py`：

* 只补 `se` / `ZenPivotCnt` 两列，**不重算** Prophet/冷启动/分钟线；
* 复用 review 的同一套函数（`hour_extra._sample_entropy_by_day` /
  `_pivot_counts`），60min 回看 900 天、目标下界 800 天，与
  `zen_snapshots_step` 同口径；
* 写库复用 `save_reality_feat`（共享写口）；
* **默认 dry-run**，`--apply` 才写。

```bash
python tools/backfill_hour_extra.py --partial            # 27 个码，看
python tools/backfill_hour_extra.py --partial --apply    # 真正补
python tools/backfill_hour_extra.py --codes 000711 --apply
```

实测工具对 `000711` 2026-10-20~23 的输出与库里 15 行**逐值一致**
（`ZenPivotCnt=5`、`se=0.008`）。

## 三、注意

* 补的是**历史** `ZenPivotCnt`/`se`，不会改变已有值；`000711` 全窗口的历史值
  是 1→5（2024-08 从 1 开始），不是“起手 >3” —— “起手 5”指的是最近的
  那一批行；这是 review 算法的真实结果。
* 当前 fast review 跑不会自动修这 27 个码：它们的行已被判“已持久化”，
  `missing_targets` 会跳过；必须显式 backfill 或 `--force`。
* 以后再加 review 契约列，应同时准备一个**只补新列**的 backfill 工具/步骤，
  不要指望 persistence 自动重算（`min_columns=1` 是刻意设计，避免每次加列
  都全量重跑）。

## 四、验证

* `--partial` dry-run：27 个码 / 47,321 行；
* **2026-10-27 已 apply**（排除 review<100 的新上市码）：**23 个码 / 47,191 行**；
  `--partial` 再跑为 0；
* `000711` 补齐后 **2,059 行** `ZenPivotCnt`/`se`（2024-08-19 起手 1 → 2026-10-26 为 5；
  近 1920 根 60min 窗口内起手 2）；工具值与库中 15 行逐值一致；
* 全量测试全绿。
