# D61. XGBoost 迁入 `analysis/xgboost/`：先落框架与特征缺口，不做特征生产/落库

- **编号**：D61
- **日期**：2026-10-21
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D61`，或直接开这个文件

**背景**：旧树（4.4）的 `xgb_scan` 由 `markup/mark_uprising.py`（标签）、
`benchmark/train_xgboost.py`（训练）、`fractal/vXI.py`（预测）三块组成。
新树没有 xgboost 代码、没有旧模型文件，review 管线的输出与旧 58 个特征
差距很大。用户 2026-10-21 定：**先搬框架 + 出缺口清单**，特征生产、CLI、
落库下一轮。

---

## 一、落地

| 旧树 | 新树 |
|:--|:--|
| `models/preprocessing.py::feature_names('xgb_scan')` | `analysis/xgboost/features.py` |
| `markup/mark_uprising.py` + `portfolio/utils.py::calc_fractal_stats(raw)` | `analysis/xgboost/markup.py` |
| `portfolio/base.py::calc_portfolio_returns`（-9..9 评分 rank） | `analysis/xgboost/rank.py`（`calc_portfolio_rank`） |
| `benchmark/train_xgboost.py` | `analysis/xgboost/train.py` |
| `fractal/vXI.py::calc_xgbclf_pred_prob` | `analysis/xgboost/predict.py` |
| `utils/path.py::cache_path` 模型路径 | `analysis/xgboost/model.py`（复用 `core/path.py`） |

约束：

* 纯 **DataFrame 进/出**，不读 8.3、不写库；
* 模块级不 import `xgboost` / `sklearn` / `matplotlib`（都在函数内惰性导入）；
* 预测**只返回 DataFrame**，落库等后续轮次；
* `xgboost 3.4` API 适配：`XGBClassifier(**params)`，去掉 `silent`/`nthread`，
  `num_class` 由 sklearn wrapper 从标签推断。

## 二、特征契约与缺口

旧 `feature_names('xgb_scan')` 有 **58 个条目**，但
`MTMPOWER30` / `MTMPOWER30_MAJOR` / `MTMPOWER30_WEEKLY` 与 `MTM_NORM` 系列
指向同一存储列 ⇒ **55 个唯一列**。canonical 名用新树常量值，旧存储名作
`legacy`；用户 2026-10-21 定废弃 **4 列**（上游链未就绪）：

`ZW_COEF_SN`、`ZW_COEF`、`DESINTY_CHAIN_LAG`、`MPWR3_MTR`。

同一天用户改判：`scoreM15`（及其两种派生）、`m9tBf`/`m9tSxBf`/`m9tBfMaj`/
`m9tSxBfMaj`、以及 `missing_producer` 里除 `ZEN_PEAK_RET_GAR*` 外的全部
（MAXFACTOR / BOLL-HMA5 / MACD lag / MA90 / MPWR3* / poly9* / mtmNorm* /
PeakLowLag / MTMMA_NORM*）都是 **derivable**（可重新计算）；`zDLagMajR` /
`m9t` / `m9tMaj` **直接采用新口径**（旧口径不追平，目标是重新训练模型）。

默认 `feature_names()` = **51 列**。状态分布（`feature_status_report()`）：

| 状态 | 数量 | 含义 |
|:--|--:|:--|
| `produced` | 5 | `zDLagMajR` / `zDLagMinR` / `zPLagMinR` / `m9t` / `m9tMaj` |
| `ambiguous` | 0 | 新口径已拍板，不再等待核对 |
| `derivable` | **37** | 基础指标 + STOCK_SCORE + M9T before + MAPOWER/MTM/Poly9/PEAK/MTMMA 等，待接线 |
| `missing_producer` | **2** | 只剩 `ZEN_PEAK_RET_GAR` / `_MAJOR` |
| `missing_source` | 7 | 资金流 + MASSIVE 数据源未搬 |
| `deprecated` | 4 | ZEN wavelet / DESINTY_CHAIN / MAPOWER30_METRIC |

⚠️ 标签侧还依赖 `ZEN_WAVELET_TIMING_LAG`、`POLYNOMIAL9_Donchian_*`、
`MAPOWER30_METRIC_CANDICATE*`、`STOCK_SCORE_PUNCH` 等**不在 55 列契约里**的输入；
`markup.required_columns()` 单独列这 21 个必需输入（另有 3 个可选）。

## 三、验证

* `calc_transcation_stats_np` 与老树 `portfolio/utils.py` **逐值相等**
  （numba 签名要求的 dtype：int16/f4/int32/int32）。
* `calc_fractal_stats(mode='raw')` 与老树**逐帧相等**（22 行 × 15 列）。
* `get_wait_all_greedy_opt/neg`、`calc_portfolio_metaphase`、
  `calc_portfolio_rank`（旧 `calc_portfolio_returns`）与老树**逐列相等**
  （老 `portfolio/base.py` 在 pandas 3 下要补 3 处环境差异才能跑，补的是运行环境，
  不是算法；rank 的 7 个输出列全部一致）。
* 新增 `PFL` 常量类（`models/alias.py`）与 `TRD.POLYNOMIAL9_CAST_BEFORE_COMPOUNDED`。
* **8.3 读取入口**：`rank_from_83(code, frequency='30min', realtime=False)` ——
  经 Active Market 读分钟线 → `macd_cross_features` 现算
  `MACD_CROSS_SX_BEFORE(_MAJOR)` → `calc_portfolio_rank`。MACD 用
  `analysis/indicators.calc_macd_qa`（QUANTAXIS 口径）；`CROSS` 补为
  `analysis/indicators.cross_above`。
* 实测 600519（30min，2025-10-01..2026-10-21）：读到 1994 根，rank 正常产出
  （-7/-5/-3/1/3/5 等）；**不写库**，返回 DataFrame。
* `markup_uprising_labels` 合成帧：标签值域、入参不被修改、缺列拒绝、
  可选输入降级。
* 训练/预测用合成特征跑通（真 xgboost 3.4.2）：保存 → 加载 → 预测概率。
* 全量 **944 条测试全绿**（skipped=1）。

## 四、本轮不做

* 特征生产（把 MAPOWER/Poly9/PEAK/基础指标接到 review 或独立 builder）；
* markup 的完整输入链（当前缺列时**明确拒绝**，不静默 NaN）；
* CLI（`--train` / `--strategy xgb`）与预测落库；
* 旧模型对拍（仓库里没有 `xgb_scan_*.pickle`）。
