# D27. 启动信息改版：**身份块 + 跨 banner 对齐的阶段列**

- **编号**：D27
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D27 DECISIONS.md`，或直接开这个文件

**起因**（用户 2026-10-09）：「这四行显示设计比较眼花，能参考一下经典 cli 软件的版权和
启动信息，设计的比较阅读友好吗？」

改版前的四行是：

```
Copyright (c) 2018-2026 azai/Rgveda/GolemQ(uant) | github.com/Rgveda | 知乎@阿财
[2026-10-09 17:29:39]: bootstrap
环境自检  操作系统 ●  python ●  … 时区 ●
[2026-10-09 17:29:39]: source: pytdx
```

**三个毛病**：① **两个戳紧挨着**（像同一件事说两遍）；② 版权/头行/数据源/状态
**四种行同字重**（没有层次）；③ 数据源是**第二行头**而不是一列。

**借经典 CLI 的三条**：`terraform` / `gh` 的**身份块 + 空行分层**、
`cargo` / `brew` 的**前缀列**（而不是把状态塞在行中间）、`journalctl` 的
**时间戳成为一列**（而不是每行各挂一个）。

**改成**（用户选定，「身份块 + 空行分层」）：

```
GolemQ  [2026-10-09 17:29:39]
Copyright (c) 2018-2026 azai/Rgveda/GolemQ(uant) | https://github.com/Rgveda | 知乎@阿财

环境自检  操作系统 ●  python ●  依赖包 ●  线程环境 ●  CPU 架构 ●  CUDA ●  时区 ●
数据源    pytdx
参考数据  stock_list ●  stock_info ●  stock_block ●  etf_list ●
K线       stock  day ●  1min ●  5min ●
```

**技术要点**：

* `core/presentation.identity(app, contact, when)` —— 身份块（末尾带空行），
  `stamp_text()` 出裸戳。**时刻戳从此只出现一次**，标的是「这一次运行」。
* `Banner(..., header=False)` —— 不打静态头行，只出阶段行。**默认 `True`**，
  所以现有用例与直接调用方一字不动（改动是加法式的）。
* `PHASE_WIDTH = 8` + `aligned_row(label, body)` —— 跨两个 banner 的**共享列**。
  `环境自检` 与 `参考数据` 恰好都是 8 列（都是四个汉字），`数据源` 是 6 列、
  由 `aligned_row` 补齐。**有一条用例钉住「两个阶段名都等于 8」** —— 破了就会参差。
* `数据源` 那行由 `run_save` 用**普通 `print`** 打，且必须在 `Banner` **建立之前**
  （banner 一活，`print` 就会搞坏它的行数记账 —— `PITFALLS.md` P22）。

**弃案**：把时间戳缩成 `HH:MM:SS`（日期在每次运行里是噪声）—— 用户否决，保留完整
`[YYYY-MM-DD HH:MM:SS]`。**弃案**：TTY 不带戳、日志才带 —— 要维护两种形态、测试翻倍。

**同批**：版权行分隔符统一成**单空格**（` | `），并加了 GitHub 链接与知乎账号。

**追加（同日）**：身份块的**版权/联系行压暗**。用 `_ANSI_GRAY`（`\033[90m`）而不是
SGR 的 `faint`（`\033[2m`）—— 两者观感同类，但 `90` 在 Windows conhost 与各种管道
终端上**渲染得可靠**，`2` 常被忽略；且与本文件里 `·` 那个灰点**同一个灰**（颜色只该
有一处定义）。**只在真 TTY 上**生效（`identity(color=ansi_enabled())`）——
非 TTY 里掺转义码是颜色规则的第一条禁忌，实测管道输出 `0x1b` 出现 0 次。

**再追加（同日，A 案）**：上面那条「跨没跨过一个开盘」的判据**已实现**为
`kline_save.allow_xdxr_shortcircuit`（`cli/commands/save.py` 用它，不再直接用
`allow_shortcircuit`）：

```
闸 = TTL 未过期  AND  上次全查在「最近一次开盘」之后
```

「最近一次开盘」复用 `kline_doc.alive_threshold('1min', now)`（今天已开市 ⇒ 今天 09:30，
否则上一交易日 09:30）—— **不新写一套交易日历判断**。

| 情形 | 判据给出的结论 |
|:--|:--|
| T-1 17:30 扫过 → T 08:30 开盘前跑 | 上次扫在 **T 开盘之前** ⇒ **跑** ✓（那一跑才是拿当天除权信息的时机）|
| T 08:30 扫过 → T 09:40 再跑 | 上次扫在 **T 开盘之后** ⇒ 跳 ✓ |
| T 17:30 扫过 → T 20:00 再跑 | 跳 ✓（除权是日级事件，当晚不必重扫）|
| 日历覆盖之外 | **跑**（保守）|

⚠️ **它保证不了"跑"、只保证"不跳"**：用户日常是**收盘后**跑（2026-10-09 明确），
那么**开盘前永远没扫过** ⇒ 当天盘中仍是旧基准。要真正做到「当天除权信息开盘前可用」，
**排程上得加一次盘前跑**（约 08:00–09:15）—— 而这一跑正好**跨过了开盘**，
上面的判据保证它**必定执行**、不会被闸跳掉。**代码与排程的分工就在这里。**
