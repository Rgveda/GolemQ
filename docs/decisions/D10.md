# D10. 实时行情落**按日时间序列集合**（`realtime_YYYY-MM-DD`）

- **编号**：D10
- **日期**：
- **索引**：[DECISIONS.md](../../DECISIONS.md) —— `grep D10 DECISIONS.md`，或直接开这个文件

> ⚠️ **2026-10-15 起三条流变一条**：腾讯 L2（`tencent_l2`）与 QMT 占位（`qmt`）
> **都已整条删除**，见 **D47**（L2 是 L1 的真子集、且比 L1 还慢）；
> 同日 **ETF 与指数也进了 L1 流**，见 **D48**。
> **本决定的实质（按日时间序列集合、`realtime_YYYY-MM-DD` 命名、`source` 是去重键的
> 一部分、先删后插）全部仍然成立** —— 改的只是「有几条流、装哪些标的」。
> ⚠️ 下面正文里那句「L2 那份重复是**刻意保留**的」**已被 D47 作废**。

**决定**（2026-10-08）：实时 L1/L2 落 8.3 的 `golemq_stock_cn_realtime`，
**一天一个集合** `realtime_YYYY-MM-DD`，每个集合建成**时间序列**
（`timeField='ts'` / `metaField='code'` / `granularity='seconds'`），行内保留
`datetime`（北京时字符串）供重采样；三条流（`tencent_l1` / `tencent_l2` / `qmt`）
**共用同一个日集合**，靠 `source` 区分。

**拒绝的方案 A：单一集合 `realtime_l1` / `realtime_l2`（2026-09-21 的写法）**
—— 名字与 4.4 的约定不符，而保留策略（`markets/StockCN/tools.py:34`）是**按集合名**删的：
它按 `realtime_{%Y-%m-%d}` 找集合，找不到就继续 miss，**连续 14 次后安静退出**。
也就是说改名会让 14 天保留策略**静默失效**（磁盘无声地涨），读取器也全线读空。

**拒绝的方案 B：按日**普通**集合（4.4 原样）** —— 能用唯一索引 + upsert、重启安全，
但 4.4 实测一天的 L1 是 **22.4M 行 / 数据 7.3GB + 索引 1.1GB ≈ 8.4GB/日**，14 天 ≈ 118GB；
时间序列是列式桶压缩，索引只自动建 meta+time 两个。

**代价与处置**：时间序列**不能 upsert、也不拦重复**（MongoDB 8.3.11 实测），
故写入改「先删后插」，且删除条件必须含**全部**去重键（`code` + `ts` + `source`）——
L1 与 L2 落在同一日集合、同一 `(code, ts)` 各有一行，少写 `source` 就会互删。
**这一条是正确性条件，不是可选优化**（见 `PITFALLS.md` P14）。

另一个**必须收窄**的地方：删除**只在「本进程首次见到该 `(source, code)`」时做**。
探针实测同规模（4,900 个 metaField 值）`delete_many` 要 **3.7 s**、`insert_many`
只要 **0.95 s**，而 L1 每 2 秒一轮 —— 每轮无条件删直接跑不动。收窄后语义不变：
进程内重复由 `last_ts` 挡，跨进程重复只可能出现在**重启后的第一批**。

**为什么 L1 与 L2 都留**：腾讯 L2 存的字段是 L1 行的**真子集**（L1 存整份快照、本就含五档），
这份重复是**刻意保留**的 —— 它是 3 秒节奏的独立流，也是**将来接替代源的位置**。

**环境约束（2026-10-01）**：MiniQMT 因监管停服，**目前彻底无数据**；替代方案（cfquant）
尚未落地且不是当前首要任务 → QMT 那条路**只保留结构**（`QMT_REALTIME_ENABLED=False`
关掉取数与订阅），既不重构也不删除。`gateway/xtquant/realtime.py` 同理（当前零调用点）。
