# Massive 择时：空仓 / 满仓 / 暴击 / 周线共振

> **一句话**：Massive 用**全市场横截面投票**算出一个连续仓位 `MasPosOnhold`（0~1），
> 用 `STAGE_MODE` 判断市场处在哪一档，用 `PosFull / PosReClear / PosBottom`
> 三个事件标记做加减仓；周线 `4QPwrln` 的截面中位数 / 众数提供**状态标签**。
>
> **四基准横向评估**（用户 2026-11-22 指定）：**沪深300 / 科创200 / 创业板指 / 中证1000**。
> 结论见第五、六节 —— **这套信号在中小盘上明显更强，在沪深300 上几乎无效**。

复现：`python tools/massive_timing_report.py`、`python tools/masquad_bull_episodes.py`

### 1.1 每码投什么票

```python
upr = QuadPreUprBf   # 上涨前奏「持续了多少根」
ep  = QuadPreEpBf    # 见顶前奏「持续了多少根」
z   = zDLagD         # 缠论笔方向的 event lag（负=向下）

bull = upr < ep                       # 上涨前奏比见顶前奏更近
bear = (ep < upr) & (z < 0)           # 见顶更近 **且** 笔向下
其余 → Ω（摇摆）
```

缺值（任一列 NaN）**不投票**，直接剔除 —— 与老树「缺值进 Ω」不同：
缺值意味着数据不足，计进 Ω 会把「没数据」当成「看不清」。

### 1.2 仓位怎么合成

```python
m_bull = bull数 / 投票数
m_bear = bear数 / 投票数
m_omega = 1 - m_bull - m_bear

bel_bull = m_bull
pl_bull  = 1 - m_bear
uncertainty = pl_bull - bel_bull = 1 - m_bull - m_bear
ds_conf  = m_bull / (m_bull + m_bear)
onhold   = ds_conf × (1 - uncertainty)          # ← MasPosOnhold
```

`MasPosOnhold` = **「看涨共识 × 确定性」**：

* 大家都看涨（`m_bull→1`）⇒ `onhold→1`；
* 多空对半 ⇒ `ds_conf=0.5`、`uncertainty=0` ⇒ `onhold=0.5`；
* 分歧巨大（`m_omega` 大）⇒ 即使略偏多，仓位也压得很低。

**强制清仓闸**：`m_bear > 0.618`（黄金分割）且占优 ⇒ `onhold` 直接置 0。

### 1.3 事件标记

| 列 | 定义 | 语义 |
|:--|:--|:--|
| `PosFull` | `m_bull > 0.618` 且同时大于 `m_bear` / `m_omega` | **满仓**信号（清仓闸的反函数） |
| `PosFullOnset` | `PosFull` 由 0 变 1 的那一根 | 满仓段**起点**；⚠️ 库里这列不全，见第七节 |
| `PosReClear` | 本零仓段与上一段之间只隔 ≤4 根 | **清仓暴击**：清仓→短暂重开→立刻再清仓 |
| `PosReClearStrict` | 同上 **且** 科创50、创业板都低于上一零仓段起点 | 新低确认的暴击 |
| `PosBottom` | `onhold <= 0` **且** `STAGE_MODE <= -0.5` | **空仓 + 横截面分档跌破最底带** ⇒ 见底 |
| `PosDeepBottom` | `PosBottom` 且 `StageModeStreak >= 3` 且 `m_bear >= 0.90` | 深底 |
| `PosProbe` | 见底时撤销强制清仓，回到 `m_bull`；否则等于 `onhold` | 试探仓位 |

`STAGE_MODE` 是**全市场逐码 `stage` 的众数**，取值 `-0.5 / 0 / 1 / 2`。
`StageModeStreak` 是「连续处在 ≤0 档的交易日数」。

**导出**：以上七列全部写进 `output/massive_timing_daily.csv`（`--csv` 生成），
连同 `PosBsln/PosPad/PosNegBsln`（`m_bull/m_omega/m_bear`）、周线 `WekMed/WekMode`、
派生清仓信号 `d_drop/d_zero/d_weak/d_reclear_d`，以及四个基准的 5/10/20/60 日前向收益。
⚠️ CSV 里 `PosFullOnset` 是**派生值**，库里的原始列另存为 `PosFullOnset_stored`
（对比两者就能看到历史行漏回填的部分）。

### 1.4 周线共振怎么算（D86）

```python
4QPwrln = (close > MA5) + (close > MA13) + ... + (close > MA233) - 3.8   # 周线
MasQuadPwrlnWekMed  = 全市场成熟码的横截面中位数
MasQuadPwrlnWekMode = 全市场成熟码的横截面众数
```

取值落在 `-3.8 + 0.1k` 的格点上（`-3.8` 最弱 ~ `4.2` 最强）。
**只算成熟码**：某码周线不足 233 根时 MA233 项恒 0、powerline 结构性偏低，
不进截面（D86）。

⚠️ **日期轴 2026-11-24 修正**：原先取 `stock_reality_feat_day`（特征表）的
distinct 日期，而那张表没跑过 review 的年份有洞 —— 600519 在 2022-06~10 只有
**10** 个日期（原始日线 103 个）⇒ 2022 大半年的周线截面整段缺失。现改取
`stock_day.date`（原始日线），2018~2026 共 **2,155** 个交易日。

### 1.5 日线 Maj 共振（2026-11-23 落库）

```python
4QPwrln = (close > MA5) + (close > MA13) + ... + (close > MA233) - 3.8   # **日线**
MasQuadPwrlnMajMed  = 全市场横截面中位数
MasQuadPwrlnMajMode = 全市场横截面众数
```

与 `run_market` 里的 `pwrln_major` **同源**：那边也是
`calc_four_quadrant_boost(annual=252)` 的日线 `4QPwrln` 按日映射到当天 4 根
60min（`feature_flow.pwrln_major`），所以 15:00 行的横截面逐值相同。

⚠️ **Maj 不做成熟度门槛**（默认 `--min-days 0`）：mainstream 的横截面包含上市
不足 233 日的码（它们的 MA233 恒 NaN ⇒ powerline 偏低）。**为了让回填值与
mainstream 逐值一致，这里不另加门槛**；`--min-days 233` 会得到更干净的截面，
但与 mainstream 分叉 —— 别只改一边。

**统一入口（2026-11-23）**：`tools/plot_mas_quad_pwrln.py` 一次算 Wek + Maj，
并输出

* CSV：`output/mas_quad_pwrln_wek_2018_2026.csv`
  （`MasQuadPwrlnWekMed/WekMode` → `MajMed/MajMode` → `n` → `MasPosOnhold`）；
* PNG：`output/mas_quad_pwrln.png`（上：Wek/Maj 四条线；下：`MasPosOnhold`
  + 仓位事件标记）。

* 历史回填：`python tools/plot_mas_quad_pwrln.py --start 2018-01-01 --end 2026-11-23 --apply`
  （只写 massive 的 15:00 行）；
* ⚠️ 主流按 bar 写**全部四根**（10:30/11:30/14:00/15:00），日内值同样是市场级
  序列；本页的 CSV/PNG 与分析只用 **15:00**。
* 日常更新：`--strategy mainstream --eval all` 每次都会重算并写 Maj 两列
  （**取数**窗口 = as_of − 1600 自然日，但**输出/落库**只保留最近 **800** 天，
  保证每根 bar 都有 233 根日线预热）；
  ⚠️ **窄口径**（`--eval fast|etc|代码清单`）时两列被置空、不覆盖历史 ——
  市场级序列只对全市场横截面有定义（`run_market(market_scope=False)`）。

⚠️ **两处口径修复（2026-11-24，用户选「修主流口径」）**：

1. **Maj 预热**：主时间轴原先包含 2 倍回看的全部 bar（约 4.4 年），窗口头部
   没有 MA233 预热 ⇒ Maj 偏低（2022-07-08 实测 -3.8 vs 0.2）。现只输出最近
   800 自然日；更早的行不再被主流覆盖（保留回填值）。
2. **Wek 成熟度**：主流的 Wek 横截面读逐码 `4QPwrlnWek`，而该列原先**不 gate**
   ⇒ 截面混进上市不足 233 周的新股。现在
   ① review 的 `day_sample_step` 与周线工具的 `--write-60min/--synthetic-60min`
   都按 233 周门槛写 NaN（`_mature_mask` 唯一实现）；
   ② 窗口内逐码 `4QPwrlnWek` 已回填（`backfill_quad_pwrln_wek.py --start
   2024-09-15 --end 2026-11-23 --min-weeks 233 --write-60min --skip-cross`）。

## 二、怎么读（把口述规则翻成列）

| 口述 | 数据判据 |
|:--|:--|
| 空仓 | `MasPosOnhold == 0`（`m_bear>0.618` 或 `ds_conf=0`） |
| 满仓 | `PosFull == 1`（`m_bull>0.618`） |
| 满仓起点 | `PosFullOnset == 1`（**用 `PosFull` 派生**，库里的列不全） |
| 清仓暴击 | `PosReClear == 1` |
| 清仓暴击·新低确认 | `PosReClearStrict == 1`（2022-06 起只有 1 次：2023-04-21） |
| 见底试探 | `PosBottom == 1` |
| 深底 | `PosDeepBottom == 1`（3 天：2024-01-23/24、02-06） |
| 周线深底 | `MasQuadPwrlnWekMed <= -2.8` |
| 熊转牛分界 | `STAGE_MODE` 前一日 `<=-0.5`、当日 `>-0.5`（用户 2026-11-22） |

⚠️ 本段数据里 `STAGE_MODE == -0.5` 的 18 天 **恰好全部等于** `PosBottom` 的 18 天
（`PosBottom` 的定义含 `onhold<=0`），两条统计是同一批事件。

### 6.6 段内清仓信号（`MasPosOnhold` 派生）

库里的 `PosReClear` 用的是**60min 的 4 根**（≈1 个交易日）作为「清仓→重开→再清仓」
的间隔，跨一天就不算。所以在日线上要自己派生：

```python
zero      = MasPosOnhold == 0                       # 空仓
weak      = MasPosOnhold < 0.25                     # 弱仓
drop      = weak & (过去 5 日最高 >= 0.5)            # 高位跳水（有效的清仓）
reclear_d = 零仓段 → ≤3 个交易日重开 → 再次零仓      # 日频版的「清仓暴击」
```

**只有 `drop` 有信息量**：`zero` / `weak` 在一整段低仓区里天天触发，拿它们当离场
会把大牛段砍掉（实测 2025-05-09 段在 2025-06-20 就 `onhold==0`，照此离场会错过
后面创业板 +64.5%）。

`drop` 在 2022-06 之后的 8 段里触发 **4 次**：

| 段 | 信号日 | 沪深300 拿住→离场 | 科创200 | 创业板 | 中证1000 | 效果 |
|:--|:--|:--|:--|:--|:--|:--|
| 2023-01-20 ~ 04-20 | 2023-03-09 | -1.6% → -3.9% | +5.6% → +3.5% | -7.7% → -8.2% | +3.4% → +2.3% | ❌ 更差 |
| 2024-09-27 ~ 2025-01-02 | 2024-11-19 | +3.2% → **+7.4%** | +25.0% → **+32.9%** | +9.3% → **+19.7%** | +12.9% → **+19.3%** | ✅ |
| **2025-01-27 ~ 2025-04-10** | **2025-03-25** | -2.1% → **+3.0%** | -0.9% → **+8.7%** | -7.9% → **+4.0%** | -1.1% → **+7.9%** | ✅ 最强 |
| 2025-05-09 ~ 2026-03-19 | 2025-09-04 | +19.2% → +13.5% | +58.5% → +30.0% | +64.5% → +38.0% | +30.0% → +15.8% | ❌ 下车过早 |

⇒ **它是风控信号，不是增收信号**：2 次救命、2 次少赚。合起来的结果是
「降低波动、削掉尾部大回撤」，而不是提高累计收益。

## 七、局限与坑（读之前先看这一段）

1. **数据起点**：massive 表 2022-06-16 才有行（1,075 天）。日频信号的样本量只有
   4~9 个，**不是统计显著**。
2. **基准可用区间不齐**：科创200 只有 2022-12-30 起（941 行）、中证1000 从 2013 起、
   沪深300/创业板最长。表里每个 horizon 都标了实际 `n`。
3. **中证2000 库里没有**：`index_day` 里 `932000` 一行都没有，用**中证1000**
   替代。两者成分不同（中证1000 是 1000 只，中证2000 是 2000 只），
   小盘弹性会有差异。
4. **基准选择会改变结论**：同一套信号在沪深300 上几乎全无优势，在科创200/创业板/
   中证1000 上边际明显。**报任何胜率都必须写明基准。**
5. **`STAGE_MODE` 只有 4 档**，`-0.5` 在 1,075 天里只出现 18 天；「83% 反弹概率」
   是 **6 个样本里的 5 个**。
6. **周线只有成熟码**（D86）：2018~2020 面板 2,200~2,500 只，2026 年 4,615 只。
7. **float32 阈值坑**：CSV 里 `-2.8` 原始存成 `-2.799999952316284`，
   直接写 `<= -2.8` 会**漏掉整个 -2.8 档**（实测 216 vs 486 行）。读表先 `round(1)`。
8. **`PosFullOnset` 落库不全**：派生应为 9 次，库里只有 3 次（2023-01-31、2024-09-27、
   2024-11-05、2024-12-03、2025-07-14、2025-08-07 这 6 次是 0）。
   **用 `PosFull & ~PosFull.shift(1)` 自己派生。**
9. **基准序列别截断**：见第五节勘误 —— 截断 + `dropna()` 会造出假优势。
10. ~~**`MasQuadPwrlnMajMed/Mode` 未落库**~~ —— **2026-11-23 已落库**（见 1.5）：
    `tools/plot_mas_quad_pwrln.py --apply` 回填 2022-06-16 起；
    `--strategy mainstream --eval all` 日常重算。窄口径跑会置空、不覆盖。
11. **窄口径不刷新市场级列**（2026-11-25）：`STAGE_MODE`、各 MEDIAN、M9T COMBO、
    `MasQuadPwrlnMajMed/Mode` 都只对**全市场横截面**有定义。`--eval fast` /
    `--eval 600519` 这类窄口径跑**不再重算**它们（置空 ⇒ 写库跳过 ⇒ 库里既有值不动）；
    要刷新必须跑 `--eval all`（或 `stock`）。快照源列现在由逐码 worker 读回，
    不再有一条独立的全表扫，所以窄口径也没法"顺手算一下"。
12. **不是投资建议**。全部是历史回看，含幸存者偏差（当前股票池）。
